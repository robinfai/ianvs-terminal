# Ianvs Web 控制台重构

2026-10-31。基线 `33f230fc6631d6c2475f53f7acd1641f5021d83a`；本地分支 `feature/webui-console-redesign`。用户选择深浅主题可切换，恢复/换机采用步骤引导，日常控制台采用清晰面板。此轮仅改 Web 前端与测试，没有重写后端认证或增加管理员权限。

## 已实现

- 统一浅色/深色 tokens、跟随系统与显式选择，使用 `ianvs.theme` 持久化；存储不可用时当前页仍可切换。
- 中文登录、注册、本地令牌连接、恢复能力说明；保留真实 begin/complete/cancel 两阶段认证及满8槽显式替换。
- 默认用户总览、三类文档服务器快照、同步/换机指引、SSH配置CRUD、安全与会话。快照只展示普通文档元信息；没有客户端遥测时明确未知。
- SSH敏感字段仍在浏览器加解密，密钥仅存在页面内存；输入密钥不代表验证成功。普通连接字段和偏好未加密。
- 会话列表、单条/其他会话撤销与退出使用真实接口；危险确认、取消初焦点、失败和部分成功反馈。
- 窄屏布局、键盘导航、表单标签、弹窗Tab陷阱与嵌套焦点恢复；桌面缩放，手机固定字号。
- 管理页面是独立预览：默认无数据，用户主动载入静态示例；不调用管理API、不读取其他用户数据、不产生变更成功。示例筛选、详情与确认说明可操作，真正管理提交禁用。

## 生产能力边界

当前User模型没有role/status/email，管理鉴权、初始化、邀请、找回、改密、账户删除、全站审计、动态配置均没有后端接口。前端不会根据用户名称或隐藏菜单伪装授权。恢复页面不收凭据、不发邮件；安全页改密禁用。管理预览对当前已登录用户可见是因为其没有真实管理数据或操作，不代表该用户是管理员。

Web不持有另一台设备的本地候选版本，冲突页只提供说明并引导到发生冲突的客户端。不能在Web“保留两份”或伪报合并完成。主密钥没有服务端恢复通道；账号恢复不恢复密钥。

## 最小后端接口契约（待实施，不是现有路由）

| 能力 | 建议接口/数据 | 必须由后端保证 |
|---|---|---|
| 服务能力 | GET /v1/capabilities；有效注册策略、可用恢复方式 | 不泄露引导凭据；能力失败不能默认开放注册 |
| 管理授权 | /v1/me 扩展明确role/status；管理中间件 | 每次请求鉴权；角色改变撤销旧会话，禁止前端自定角色 |
| 受控初始化 | POST /v1/setup/complete；一次性部署者引导能力 | 短期单次、事务唯一，不自动提升首个普通注册者 |
| 账户管理 | GET /v1/admin/users；POST users/{id}/disable、restore；PATCH role | 仅元信息、版本前置条件、再认证、审计；最后管理员不能归零 |
| 恢复/改密 | 可信核验后签发重置凭证；用户凭证消费/当前密码改密 | 单次/过期/限流，成功撤销全部会话；不处理主密钥 |
| 邀请/删除 | 单次邀请生命周期；删除任务状态 | 不默认授予管理员；删除确认后隔离/撤销，永久影响与备份政策明确 |
| 配置/审计 | 只读有效配置来源；分页脱敏事件 | 不含DSN、密码、token、operation_id、恢复凭证或业务正文 |
| 客户端同步状态 | 可选最小上报协议 | 不把会话备注当硬件身份；未上报就是未知，明确采样时间 |

后端实施前不得启用管理写按钮。仓库采用唯一current schema，后续模型变更须另行评审数据保留措施，本轮不做数据库迁移。

## 运行与验证

```sh
cd backend/webui
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test:unit
pnpm build
CHROMIUM_PATH=/usr/bin/chromium pnpm test:ui
```

`test:ui` 启动隔离Vite并在浏览器中拦截API，验证9个UI场景；明确是mock接口，未使用真实用户。`UI_CAPTURE_DIR=/absolute/path` 可保存深浅色/桌面/移动截图。

真实接口测试沿用 `tools/verify_data_api_webui.sh` 和 `backend/webui/e2e/playwright.config.ts`，可通过 `GO`/`PNPM` 指定工具链，`CHROMIUM_PATH`指定Chromium；默认仍使用Chrome channel。本次另用隔离运行器在全新临时SQLite执行3项真实E2E，包括加密CRUD、错误密钥、重登、容量和撤销，无跳过。相关日志与截图在交付包中。原有6项单测也通过。

`pnpm dev` 仅启动前端，登录需要同源真实API，不能用静态开发服务器冒充认证服务。生产集成使用 `pnpm build` 后Go内嵌的dist。管理演示数据由前端独立提供，与认证API fixture不同，均明确标注。

无独立lint脚本；执行TypeScript、单测、构建、真实/模拟浏览器验收和 `git diff --check`。未推送、创建PR、合并或部署。
