# 09 · Codex 完成后的 GitHub 复核手册

本文件用于后续用户明确要求检查最新代码时启动复核。当前没有设置自动监控，也没有提前判定未来实现会通过。

## 1. 首先确认审查的版本

获取用户指定分支当前 HEAD，不使用聊天中的旧 SHA 冒充最新。读取 `STATUS.md`、`results/FINAL_REVIEW.md`、`evidence/manifest.json` 、`plan.json` 与 `shotlist.json`。记录文档基线、最终实现 C、证据 E 和最新 HEAD H。

如果 H 比 C/E 新，检查增量 diff；代码、测试 harness、依赖或构建配置变化使相关旧证据失效。仅文案/证据文件变化也要确认未篡改历史结果。最后结论必须明确针对 H 还是 C，而不是泛称“仓库没问题”。

## 2. 审查顺序

先查安全/运行边界：写入所有权、只读 surface、revision、目标绑定、unknown receipt、取消和重连。随后查主流程和输入法。再查响应式/主题/可访问性。最后验证证据覆盖、构建与文档一致性。

代码重点入口：`shell_screen_ai.dart`、`terminal_ai_workspace.dart` / 拆分后对应组件、AI controller/runtime/approval、composer controller/view、compact blocks/reader、terminal mode、mobile input/navigation、canonical 与生成镜像。

不能因为文件名变化就判不存在：从当次最新 tree 查真实入口并跟踪调用链。不得只检查测试快照，不查看生产组装路径。

## 3. 十个反向问题

1. 点击 AI 诊断是否仍只是准备草稿，零模型调用与零 PTY 写入？
2. “查看终端”是否真的不能写键盘、粘贴、鼠标报告，而且不偷偷暂停 AI？
3. “接管”是否撤销排队写入，却不自动给正在跑的命令 Ctrl+C？
4. 两次批准、陈旧 revision、目标切换是否仍最多一次有效提交？
5. 回执未知后重连/继续任务会不会重放命令？
6. IME 候选回车是否被快捷键捕获？有没有真实系统键盘证据？
7. 手机 six-line preview、原生分页、淘汰标记和复制是否被美化逻辑破坏？
8. UI 是否把模型“成功”画成退出码成功？引用是不是冻结的真实来源？
9. 草稿、选区、阅读锚点是否在旋转、任务切换与只读返回后保持？
10. fixed phone fonts、macOS Composer、iPad 分栏与 canonical mirror 是否回归？

## 4. 证据检查

运行校验器（工具/文件可用时），并人工打开全部关键原图：不是设计稿、不是旧图、不是裁过主操作的局部图。核对 case、环境、commit、实际截图大小、SHA、日志计数。动态用例看录屏中段，不只看封面。

重点交叉对照 S1-T05/T06/T08/T09，S2-T03/T05/T07/T11，S3-T05/T07，S4-T01/T04/T05/T06/T09/T10/T14。抽样不代表可以跳过 48 场景覆盖检查。

需要真实设备才能判定的部分，在仅能读 GitHub 时以“检查提交的实机证据”描述；不能说评审者亲自运行过实机。若关键视频无法访问，说明不足而非猜测通过。

## 5. 问题输出格式

| 严重度 | 需求/用例 | 源码证据 | 图片/视频证据 | 问题与影响 | 修复及重验 |
|---|---|---|---|---|---|
| P0/P1/P2 | Sx-Rnn / Sx-Tnn | 当次 H 的文件与最小行范围 | 实际证据路径和时间戳 | 区分已复现、静态风险、证据缺失 | 精确受影响用例 |

结论使用：`通过`、`有条件接受（非核心遗留）`、`需要返工`、`证据不足，不能验收`。零证据不等于零缺陷；测试全绿不自动等于产品通过；缺图也不直接证明代码错误，应分开陈述。

## 6. 最終发布判断

所有 P0/核心 P1 关闭；全部必要用例通过；实机、日志和版本一致；已知限制准确；证据后没有未验证代码变化。否则给最短补证/修复路径，不要求无关重做、不用“建议看看”替代明确阻塞项。

## 7. 逐帧与文档检查

依照 10 检查 110 个可见状态，不只统计图片数量。用 validate_shotlist.py 检查声明覆盖和阶段报告嵌图；人工核对同一原图复用是否真能覆盖那些状态。11 的 observer 写入归因和有效 operation 计数用于复核日志，不能将底层 write 次数误当执行次数。
