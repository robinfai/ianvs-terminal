# 07 · 验收矩阵与可复现测试计划

全部 48 个场景初始均为 `not_run`。每项要求真实步骤、对应环境截图和可核对的行为断言。`plan.json` 是机器读取的覆盖定义，不得为追求通过而删除场景或降低来源等级。

## 测试数据与固定 fixture

主机命名用 `dev-box` / `node-a` / `node-b`，路径用一次性 `~/trail-prd-demo` 或测试容器目录。所有记录中的 IP、账号和密钥不得来自生产。命令种类至少：确定失败、确定成功、长输出、多行、Unicode、无输出、持续输出、真实 TUI。

确定性边界测试使用 mock LLM；真实模型 API 和桌面 ACP 仅补独立端到端冒烟，不把两者混写。建议实现测试专用安全命令 `trail_fixture`（脚本或现有测试工具）：`fail` 退出 7 并写固定错误；`inspect` 输出固定环境；`stream` 按受控速率输出；`emit` 生成多页/Unicode/无换行输出。只有隔离 fixture 环境添加该工具，生产不硬编码这种命令，也不依赖模型恰好生成某个工具。

真实 TUI 使用测试环境确认已安装的 vim/top；缺工具应安装到隔离环境或明确阻塞，不能用预录文本装成正在运行的 TUI。

## 用例层级

Unit/controller：意图路由、revision、身份校验、状态转换、去重。Widget：布局、语义、边界尺寸、按钮状态。App integration：真实路由、原生 core、SSH、回执与 Block。系统/实机：IME、VoiceOver、键盘、前后台与性能。覆盖高层并不免除关键低层不变量测试。

## 回归组合与缺陷分级

S1–S3 修改公共组件后重跑所有受影响场景，最终 S4 候选回归全部 48 项。多环境组合不是每次笛卡尔积穷举：手机核心宽度/主题/键盘组合优先，固定列表不可省略；额外组合按风险补充并记入 manifest 的 additional_cases。

P0：误提交、错目标、重复执行、权限绕过、密码/凭据泄漏、历史错误绑定。P1：审批/输入/阅读主路径阻断、草稿丢失、控件不可达、严重溢出/崩溃。P2：非阻断视觉或效率。测试 harness 错误与产品错误分开报告，修复 harness 后重跑，不能把失败样本删除。

截图和测试数量不作生产质量替代指标。用例达成依赖行为断言、来源和实测结论，不依赖“总共多少测试全绿”的口号。
