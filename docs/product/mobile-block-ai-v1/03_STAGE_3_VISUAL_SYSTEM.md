# S3 PRD · 统一视觉语言与状态体系

**阶段目标：** 用户一眼分清命令、输出、AI 建议和真实执行状态，而不是所有内容都长成相同的聊天卡片。  
**依赖：** S1 行为合同、S2 布局结构稳定。  
**非目标：** 换品牌、全站重做、把手机界面强塞桌面 Dock、用设计稿图片替代 Flutter 控件。

## 1. 设计原则

安静的终端底色，清楚的文字层级，少量状态强调。AI 是任务解释与建议，不是给每个块加发光边框。主色遵循应用当前主题，不能另造与宿主不一致的固定蓝色。

正常/成功块使用轻分隔；失败只强调状态文字、图标与诊断操作，不整块红底，不加左侧高亮色条。Composer 聚焦靠文本光标与合规焦点语义，不恢复曾去掉的蓝色外框、下划线。键盘焦点可使用宿主既有非侵入焦点提示，不能为“极简”让焦点不可见。

## 2. 需求

### S3-R01 · 语义 tokens（P1）

先盘点 `AppThemeTokens`、ColorScheme、`ComposerTheme`、Typography 与已有图标资源。新增的是真正缺失的语义角色，而非每个组件一套色值。

| 角色 | 语义 | 规则 |
|---|---|---|
| surface.base / panel / overlay | 内容、编辑器、临时层 | 深浅色分别映射；避免三层同时强阴影 |
| text.primary / secondary / disabled | 主内容、元信息、不可操作 | disabled 仍保留 readable label |
| border.subtle / strong | 分隔与需注意的边界 | Error 不通过粗色框表达全部状态 |
| action.primary | 当前主要可执行操作 | 采用、发送、执行不能只改颜色不改文字 |
| status.running / pending / success / danger / unknown | 执行/审批语义 | 每项必须有文字或可访问名称 |
| focus / selection | 焦点与选区 | 不与警告/成功混淆 |

生产组件不得散落硬编码颜色。示例 HTML 的色值只是视觉样例，不是生产 token 取值来源。

### S3-R02 · Command Block 结构（P1）

标题区：命令（最多两行）+ 状态 + 更多。输出区：原生 TerminalViewport、手机末尾六行。状态/操作区：必要耗时/退出码、失败快捷 AI、完整输出入口。

成功、失败、运行中和未知分别表达；未知退出码不显示成功勾。空输出显示“无输出”或“等待输出”，不伪造空白终端高度。输出 ANSI 样式和 OSC 链接保留；主题不能把语义 ANSI 色全改成品牌色。

### S3-R03 · 主动作与输入去向（P0）

固定文案：`采用`、`执行`、`发送给 AI`、`补充要求`、`审阅命令`、`执行一次`。在正常手机宽度保留短文字；极窄场景确需仅图标时，旁边必须有可见的模式/去向说明，并保留可访问 label。

禁用说明在相关区域明确给出，例如“Shell 正在运行，暂不能提交命令”，而非只有浅灰箭头。没有功能的下拉箭头、渐变按钮和图标不得出现在实现里。

### S3-R04 · 任务时间线层级（P1）

用户请求是任务起点；AI 解释作为正文；拟执行动作是待审批操作；原生 Block 是执行事实；最终总结包含有效证据入口。不要给五类内容套同样的外框和密度。

已完成步骤允许紧凑显示为“3 条命令 · 2 成功 · 1 失败”，展开仍指向原 Block，不复制日志。当前待审批/运行步骤保持可见入口。任务分组只是展示，不能改变数据归属、审批范围或上传范围。

### S3-R05 · 状态文案与优先级（P0）

显示优先级：回执未知 / 目标变化 / 连接不可用 > 待审批 > 运行与推理 > 空闲。普通补全 loading 不得覆盖提交结果未知。进度不可编造百分比。

| 内部事实 | 可见文案 | 允许动作 |
|---|---|---|
| 已发送，未确认 | 正在提交 | 检查状态，不重发 |
| AI 推理未结束 | AI 正在分析 | 暂停 / 补充要求 / 只读查看 |
| 提案需批准 | 有 1 条命令待审阅 | 审阅 / 拒绝 |
| shell 正在执行 | 命令运行中 | 查看输出 / 显式中断 |
| 取消推理但命令仍跑 | AI 已暂停，命令仍在运行 | 继续任务 / 接管 |
| 确定完成 | 已完成 · 退出码 0 | 阅读 / 复制 / 插回编辑 |
| 非零退出 | 执行失败 · 退出码 N | AI 诊断 / 查看输出 |
| 结果未知 | 提交结果未知，可能已执行 | 检查原提交 |
| 支持恢复 Blocks | 可返回 Blocks | 用户主动返回 |

### S3-R06 · 文案与本地化（P1）

中英文都使用动作导向的短句。用“只读查看”而不是含糊“切换”；用“暂停 AI，命令继续运行”而不是“停止”。布局测试包含较长英文与中文路径，不只用三字占位符。错误原因提供短摘要和详情，不原样曝光敏感 provider 响应体。

### S3-R07 · 手机固定字号（P1）

本轮设计起点：普通正文 15–16、代码 14、元信息 12–13 逻辑点；具体映射优先项目既有值，变更需记录。手机跟随固定字号，系统字号变更不引起 UI 自动放大。**已有用户主动的终端字号缩放仍保留**，它不等于系统 Dynamic Type。

VoiceOver 语义和读序依旧必做。iPad/macOS 检查 1.0、1.5、2.0 文字缩放；不能把手机 clamp 全局应用到其他端。

### S3-R08 · 对比、动效与焦点（P1）

本轮质量阈值：普通文本对比 ≥ 4.5:1，关键图形/控件边界 ≥ 3:1，作为项目验收目标，非“本轮已符合所有无障碍标准”的宣称。使用实际 token 组合测量并提交报告。

普通过渡建议 120–180ms；减少动画时取消不必要位移和大面积淡入，只保留必要状态变化。不以动画终点决定是否执行。审批撤销、页面变化后焦点落到有意义位置；滚屏输出不得持续刷屏播报。

### S3-R09 · 组件状态册（P1）

建立真实 Flutter previews：Block、ContextChip、TaskHeader、TaskStatus、ComposerShell、ProposalCard、ReviewPage、ReaderHeader、Empty/Error。分别覆盖 default/pressed/focused/selected/disabled/loading/error，预览使用受控数据，不访问真实账户。

现有图标族优先复用，不交付字体文件或引入未知授权资产。静态 PNG 仅文档参考，运行时不得整图铺作 UI。

### S3-R10 · 跨端一致而非同形（P1）

手机减少长期驻留工具栏；iPad 宽屏双栏；macOS 保留三层 Dock 和桌面快捷键。共同的是状态语义、动作文字、token 角色与来源模型，而不是把所有边距和栏位强制相同。

对受影响 canonical 组件运行镜像生成/一致性检查；共享修改不能只在手机 preview 通过。截图基线按真实 OS / Flutter / 字体来源分别生成，不复制其他系统 golden 冒充同环境。

## 3. 几何与视觉起点

间距使用 4/8/12/16/24；主要面板圆角 12，次级组件 8，主界面轻分隔而非重投影。触控区域至少 44×44。正文与代码的基线、行高统一；长文字优先换行/详情，不降低字号。所有这些是可经 QA 微调的设计参数，不修改执行合同。

## 5. 实施路线

先输出 token 盘点和差异记录；再收口公共小组件；再替换界面组合；随后生成同数据深浅色 fixtures，人工复核代表图；最后真实 App 重跑关键交互，证明抽组件没有影响焦点和控制器生命周期。

不要一次拆光 `terminal_ai_workspace.dart` 再补测试。按 Header、Status、Composer、Proposal、Review 等可独立验证的切片推进。

## 7. 退出条件

十个用例通过；无无功能装饰控件、无主题硬编码扩散；关键文字与状态有可访问名称；文档包含 before/after、token 对照、允许差异及未解决问题。重要状态外观与 PRD 一致，且未破坏 S1/S2 的行为用例。
