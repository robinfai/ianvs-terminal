# S4 PRD · 真实设备验证、证据提交与交付门槛

**阶段目标：** 在实际手机、iPad 与桌面环境中证明前三阶段的体验，不再用“源码存在”“组件截图好看”代替真实可用。  
**范围：** 系统输入法、触控/外接键盘、VoiceOver、生命周期、SSH/TUI、性能、数据边界、GitHub 可复核交付。  
**非目标：** 承诺 iOS 无限后台运行、承诺全机型全 OS 已测、重新跑无关模型排行榜。

## 1. 环境与前置条件

测试只使用隔离开发构建、一次性 SSH 主机/容器、无生产价值的数据与最小权限账号。不要覆盖用户安装版、真实 SSH 配置、既有密钥、录制库或当前工作会话。需要设备安装/真实服务凭据时使用用户已经授权的测试范围；缺失资源记为阻塞，不伪造。

最低验收环境：一台真实 iPhone（优先现有 iPhone 17，但实际机型如实填写）、一台真实 iPad（涉及 S2 双栏）、一台真实 macOS 主机；另补最小宽度/旧支持系统模拟器检查。支持版本窗口遵循仓库当次 `APPLE_PLATFORM_COMPATIBILITY.md`，不是按本包日期猜测系统版本。

**若没有 iPad 实机，只能判定 iPad 实机验证未完成；不能用 macOS 改尺寸代替，也不因此删除其他已完成成果。** 旧系统不可得时列出具体未测组合，最终状态为 blocked / implemented_unverified，不写“全平台已验证”。

## 2. 需求

### S4-R01 · 构建与证据身份（P0）

冻结实现 commit C；记录工作树 clean、构建模式、Flutter/Dart/Rust/Xcode 版本、测试设备、OS、App 版本与 bundle identity。截图、日志和视频全部绑定 C。后续 evidence-only commit E 可添加文档证据，但不得夹带未测试产品代码。证据后代码再改需重跑影响面。

### S4-R02 · 真实 iPhone 核心流程（P0）

从 SSH 会话开始，通过 App UI 执行一个确定失败命令，准备 AI 诊断、显式发送、审阅提案、批准、读真实结果、查看引用、返回原块。至少一次真实模型 API 冒烟；另用 deterministic mock 验证可重复错误情况。两者分别标记，不能声称 mock 是真实模型。

原始录屏展示连续路径，不允许把多个独立 fixture 页拼成“完整流程”。禁止通过后台 controller 直接调用来冒充 UI 操作。

### S4-R03 · 中文输入法（P0）

实机系统拼音输入、候选确认、删除 composing 片段、中文路径、emoji、复制/粘贴多行、撤销重做。记录实际键盘布局与 OS。按候选确认回车时写入计数与模型调用计数不增加；点击明确主动作后才增加一次。

### S4-R04 · 旋转与触控（P1）

输入中、审阅中、阅读历史中分别旋转；测试安全区、软键盘与收起键盘；长按选文、拖选、点击省略号和返回手势。操作后核对草稿值、selection、reading anchor 与 pending proposal revision。

### S4-R05 · VoiceOver（P1）

通过 VoiceOver 完成失败块 → 诊断 → 审阅 → 批准 → 找结果，不只查 Semantics 标签是否存在。读序正确、名称独立、disabled 可辨；弹层打开焦点落标题/主要内容，关闭回触发点；审批状态变化有一次适当提醒，日志滚动不无限播报。

提交连续录屏/可用音轨及人工步骤记录。系统限制无法录音时写清限制，附逐步观察记录；不能将自动语义树测试当作读屏实测。

### S4-R06 · 网络故障与重连（P0）

分别在 LLM 请求前/中、待审批、PTY 提交确认前、命令运行中断网。区分 AI 连接失败和 SSH 状态未知。恢复后先核对原回执与目标，再允许新操作；重连创建的新 Session 不默默继承旧 write guard。

远程命令是否持续由实际 SSH/进程环境决定，不伪造已停止或已成功；已淘汰的输出只标不可用。切换网络测试仅断开测试连接，不干扰用户生产连接。

### S4-R07 · 前后台、锁屏与进程死亡（P0）

至少短锁屏与较长后台各一次，报告实际时长。回前台刷新连接、输入所有者、目标与提案有效性；暂停恢复不自动重放已发送内容。iOS 系统可能挂起 App，本轮不承诺持续后台推理/SSH 保活。

杀进程再启动是另一条用例：本轮会话/任务草稿主要在内存，不承诺恢复；页面不能将新 PTY 伪装成旧任务继续运行。任何新的持久化设计单独提案，不在验收阶段临时扩大范围。

### S4-R08 · TUI、密码与人工接管（P0）

用测试主机真实 vim/top 或已明确可用的等价 TUI，验证 alternate screen、滚动、光标与退出恢复。人工接管撤销 AI 后续写入，Ctrl+C 是单独动作。密码测试用一次性账号且避免拍到密码；输入 sink / model context 日志不得保留秘密。

### S4-R09 · 大输出与保留边界（P1）

受控 fixture 生成跨多页输出和超过 scrollback 保留范围的输出；记录配置，不为测试悄悄扩大产品内存上限。验证 Reader 懒读取、全部保留输出复制、跨页一致性、ANSI、中文行和无末尾换行。旧输出淘汰显示准确提示，不出现“0 行所以执行成功”。

### S4-R10 · 故障注入与执行安全（P0）

固定测试：重复批准、陈旧 revision、目标切换、手动输入竞争、回执丢失、迟到请求、部分 send_keys、断连重连。日志关联匿名 Session/Task/Operation/Block id 和状态，证明无未授权写入、无重复有效提交。

截图只能证明按钮与文案；“没有重复执行”必须由 guarded submit/原生操作计数或受控测试断言证明。不能只看一次退出码为零。

### S4-R11 · 性能与稳定性（P1）

真实设备 profile 构建测量；发布构建补冒烟。debug/simulator 数据不得推断实机流畅度。测试基线与候选相同机型、OS、构建模式、输出 fixture、网络条件。

| 场景 | 样本 | 本轮目标（不是当前实测结论） |
|---|---|---|
| 基本滚动与局部状态更新 | 预热后 60 秒 × 3；128 个保留块 | UI 和 raster 分别 p95 不超过实测刷新预算；超过预算帧比例 ≤ 2% |
| 页面导航与本地反馈 | 每类 ≥ 30 次 | 点击到首个可见本地反馈 p95 ≤ 100ms；不含模型/网络等待 |
| 持续输出阅读 | 受控速率约 100 行/s × 10 分钟 | 可滚动、可暂停跟随；无崩溃、无无界增长 |
| Reader/审批/任务切换循环 | 20 次 × 3 组 | 清理后的稳定保留内存相对预热基线增幅 ≤ max(15%, 20MiB)，无单调泄漏趋势 |

记录观察到的刷新率与热状态；60Hz 的预算约 16.7ms，120Hz 约 8.3ms，不把设备支持的最高刷新率当采样时真实值。UI 与 raster 是不同管线，不简单相加冒充帧时间。性能录屏另跑，避免把录屏开销混入基准。

如基线本来不满足目标，仍报告失败与相对变化；先定位原因和提出调整，不为通过擅自改阈值。完整 trace 可外部附件保存，仓库中至少有关键曲线截图、统计 JSON 与可用的稳定引用。

### S4-R12 · iPad 实机（P1）

真实 iPad 窗口宽窄变化、双栏、外接键盘、指针、触控、文字缩放（非手机）独立验证。右栏只读时不能通过外接键盘或鼠标报告写入；转为人工接管有明确状态。

### S4-R13 · macOS API / ACP 回归（P0）

用已有 API 与本地 Codex ACP 各执行一条核心路径；记录实际支持环境，不新增手机 ACP。保留原 Composer UI、真实 PTY、输入法与分屏 gates。运行 `make verify`，聚焦通过不能替代完整 gate；无法运行记录具体失败/阻塞。

### S4-R14 · 数据和回滚（P0）

本轮主要 UI 变更不主动引入数据格式迁移。使用隔离数据目录验证 Profile、录制、布局和 AI 设置未被破坏。回滚到前一可用构建后只恢复配置/新会话，不恢复已死亡执行。实验开关应复用现有模式策略或最小实现，不遗留两个同时写终端的路径。

### S4-R15 · GitHub 可复核交付（P0）

所有 requirement → case → screenshot/video/log → implementation file/commit 的映射完整；`STATUS.md`、`results/S1…S4.md`、`evidence/manifest.json` 和原图都在 GitHub 可访问路径。不能只写“截图在本机 /tmp”。

每阶段给独立结论：`verified`、`implemented_unverified`、`blocked`、`failed`。任何必要实机或完整 gate 缺失，最终不得标为 verified。自动校验器通过只代表文件/覆盖合同满足，仍须人工检查截图与行为。

## 5. 发布门槛

全部 48 个固定用例满足其最低证据类型和行为断言；S4 十四项全部执行，必需真实环境可核对；零开放 P0 / 核心 P1；P2 有明确列表及产品负责人接受记录；完整 gate 通过且没有证据后代码变化未验证。仅“可以演示”或“AI 自评完成”不算交付完成。

最后提交 `FINAL_REVIEW.md`：实现 commit、证据提交、测试范围、原始图入口、实际设备、已知限制、回滚路径和最终判定。让后来只访问 GitHub 的评审者不需要猜测截图来自什么构建。
