# S1 PRD · 手机端 Block × AI 核心闭环

**阶段目标：** 一条自然的“失败 → 诊断 → 审阅 → 执行 → 结果”链路。  
**依赖：** 阅读 00、06；在最新 composer 上确认既有行为，捕获变更前同场景画面。  
**不做：** 第二套 AI 终端、云端执行服务、手机 ACP、取消所有审批。

## 1. 用户故事与成功标准

作为手机上的终端用户，我看到失败命令后，无需复制日志或寻找复杂菜单，就能把正确的输出交给 AI；执行前看到完整命令和目标，执行后知道结果来自真实终端而不是模型猜测。

从已可见失败块到“诊断草稿已准备”只需一次点击；准备草稿零网络推理、零终端写入。用户显式发送后才发生模型请求。单次批准最多产生一次有效提交。读取旧内容不会被新输出抢走位置。所有指标在 fixture 下测量，不把模型响应时间混成界面操作延迟。

## 2. 界面范围

保留现有 Blocks 主列表、AI Workspace、全屏 Reader 与 Raw Terminal。采用一个清楚的工作流，不要求 S1 先合并所有输入控制器。S2 才收口输入容器与响应式。

失败 Block 下直接显示 `AI 诊断`，旁边最多一个次操作 `查看输出`。成功 Block 默认不额外添加整排按钮；现有菜单保留。任务页面标题表达目标，状态条表达 AI 与命令的不同状态。关闭图标必须明确实际行为，不能用一个 X 同时表示“收起”和“取消”。

## 3. 详细功能需求

### S1-R01 · 失败 Block 快捷诊断（P1）

适用已完成、退出码非零的块；运行中块不显示可执行的“纠正”。按钮必须有文字与足够触控区域。点击不重新执行失败命令，不自动调用模型；没有 AI 配置时仍能保留诊断草稿并引导配置。菜单入口同时保留，正常块通过菜单“询问此块”。

命令标题最多两行，原文不能改写；超出可点详情。只提升失败入口，不把所有非零码描述为严重事故。

### S1-R02 · 诊断上下文准备（P0）

绑定 `sourceSessionId + blockId + retained output range + snapshot identity`。呈现来源 Chip：命令片段、行范围、是否截断/淘汰。可查看详情或删除。已有非空草稿不得被自动替换：附加块并提供“插入诊断问题”；空草稿可填入“解释这条命令失败的原因，并提出修正”。

两个不同会话的相同 blockId 不能混用。来源只读；用户尚未发送前不能刷新成别的块。敏感密码与未知来源数据使用现有边界，不能扩大自动上传范围。

### S1-R03 · 发送路径与任务归属（P0）

显式主按钮为“发送给 AI”。发送后冻结本轮提示词和上下文来源，草稿清理只影响已发送 revision。迟到结果不得清除新草稿。诊断可继续当前任务，但必须能看见当前任务标题；用户新建任务不清空 Shell 历史。

手工命令走现有 guarded PTY，不经模型；只有用户主动选择命令意图且满足 shell 条件时执行。附有上下文的输入保留 AI 语义，不能意外变成 shell 命令。

### S1-R04 · 审批界面（P0）

手机时间线保留简短提案，主操作为“审阅命令”；进入全屏审阅，不直接在截断三行的卡片上批准。审阅页顺序：目的 → 主机/节点/目录 → 风险说明 → 完整原始命令 → 固定底部操作。

底部为“拒绝 / 编辑 / 执行一次”。完整命令可滚动、选择和复制；可读折行仅改变展示，复制和执行字节不变。风险不只靠颜色；Smart 审阅结果写“智能审阅通过 / 仍需确认”，不显示“绝对安全”。处于查看详情/来源阶段不会自动批准。

### S1-R05 · 编辑、批准和防重复（P0）

编辑保存产生新 proposal revision，旧审批即时失效；保存不执行。批准时重新校验目标、租约、操作版本与输入代数。快速双击、延迟回调、返回旧审阅页均只允许有效 revision 执行一次。按钮提交中不可再次操作。

### S1-R06 · 执行结果回到原生 Block（P0）

提案被接收后显示“已提交”，直到原生结果到达才显示运行/完成/失败。AI 计划与终端结果不可分别复制同一份日志形成伪双份记录。已有 `CommandBlockTimelineItem` 通过稳定来源引用 Block；可收起已完成任务步骤，但原始输出可达。

AI 总结必须能打开有效证据引用；未知或非法引用不伪装为可点击证据。绿色成功只能来自确定退出状态，不来自“模型说成功”。

### S1-R07 · 只读观察、暂停和人工接管（P0）

新增显式 `查看终端（只读）`。仅变更显示，不调用 takeOver、不获取 PTY write sink。进入时清除可能挂起的编辑写入；任何键盘、粘贴、鼠标报告都不得穿透到只读 surface。

`接管输入` 明确暂停 AI、撤销排队写入，保留已经运行的命令；用户确认接管后才交出 write owner。`暂停 AI` 只停止后续 AI 动作，不发 Ctrl+C。`中断命令` 是独立操作，显示作用命令并通过现有输入协议发送一次中断。无法拆开显示与控制的路径，保留明确“暂停 AI 并返回终端”，不能伪称只读。

### S1-R08 · 阅读位置与新内容提示（P1）

用户向上滚动后取消 tail follow；新提案只展示“1 条待审阅”入口，不强制滚动、不弹键盘。点入口定位提案并记住返回锚点；返回恢复同一任务/块/行附近，允许最多一行高度偏差。切换任务、读证据、查看原始终端都保留内存草稿。

### S1-R09 · 未知回执（P0）

单独状态“提交结果未知，可能已执行”。主动作只能“检查原提交”，不允许“重新执行”。保持 operation/submission identity；重连先读取既有回执，有确定未执行证据才生成新的用户可审阅操作。禁止用普通失败重试 UI 覆盖。

### S1-R10 · 目标变化（P0）

显示原目标与现目标差异，主机、节点、cwd 不用一个长省略号隐藏全部。旧提案失效；“在当前目标继续”表示重新读取与重新规划，不批准旧命令。只有与已接受 Block 绑定的可信 cwd 变化沿用现有特殊处理，不扩大到任意目录事件。

### S1-R11 · 原始 Terminal / TUI 回退（P0）

沿用 alternate screen、mouse reporting、无法归属输出等回退原因；TUI 获得完整几何区域，不在六行卡片内伪运行。退出后提供“返回 Blocks”，不自动跳转。只读观察与真正 TUI 接管分开。AI 覆盖层开关本身不随意更改底层 PTY 行列数。

### S1-R12 · 错误、空态和配置（P1）

无配置、认证失败、网络失败、模型响应错误、Shell 不可用分别给准确文案与下一步。设置保存不发送遗留草稿；AI 错误不删除真实 Block。手机不可选择不受支持的本地 ACP 执行能力；桌面设置不因此删除。

## 4. 关键状态表

| 状态 | 主操作 | 次操作 | 绝不自动发生 |
|---|---|---|---|
| 诊断草稿 | 发送给 AI | 看上下文 / 返回 | 推理、写 PTY |
| AI 正在分析 | 补充要求 | 暂停 / 只读查看 | 自动批准高风险动作 |
| 待审批 | 审阅命令 | 拒绝 | 截断卡片直接执行 |
| 审阅完整命令 | 执行一次 | 编辑 / 拒绝 | 沿用旧 revision |
| 提交中 | 禁用批准 | 查看状态 | 重发 |
| 命令运行 | 查看输出 | 暂停 AI / 显式中断 | 把暂停当中断 |
| 结果未知 | 检查原提交 | 只读查看 | 自动重新执行 |
| AI 已暂停 | 继续任务 | 人工接管 | 自动恢复写权限 |

## 5. 设计参考

见 [D1-01～D1-03](05_DESIGN_REFERENCE.md#阶段一) 与 [阶段一设计册](design/stage-1.html)。示例中 `dev-box`、`~/demo` 为假数据；数据含义与动作文字具约束力，像素外观只是设计起点。

```text
失败块：curl http://127.0.0.1:8080/health
退出码 7 · 0.1s
Connection refused
[AI 诊断]                 [查看输出]
        ↓ 仅准备草稿
[上下文：curl… · 末尾 6 / 20 行 ×]
解释失败原因，并提出修正。      [发送给 AI]
        ↓ 显式发送
待审阅：检查本机监听端口        [审阅命令]
        ↓ 全文审阅
目标 dev-box · ~/demo
lsof -nP -iTCP:8080 -sTCP:LISTEN
[拒绝]       [编辑]          [执行一次]
```

示例展示诊断动作，并不保证所有测试主机都安装 lsof；实际端到端测试使用包内定义的可控 fixture。

## 6. 建议代码落点与实施顺序

先扩状态及边界测试，再改入口与路由，最后调样式。主要检查 `command_blocks_compact.dart`、`command_blocks_controls.dart`、`terminal_ai_workspace.dart`、`shell_screen_ai.dart`、`terminal_ai_controller.dart` 与现有 runtime/approval。新增组件应是这些控制器的 view，不引入第二个 execution loop。

先证明只读 surface 不能写入，再拆开关闭行为。现有 `takeOver()` 的安全语义保持；其他调用点不能因为新“收起”按钮而悄悄取消防护。
