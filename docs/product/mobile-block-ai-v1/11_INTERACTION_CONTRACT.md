# 11 · 交互状态、控制权与异步事件合同

本文件细化既有 S1/S2/S3 的执行安全与可预测交互；不要求引入新的执行引擎、公共协议或全局状态管理框架。字段名是分析用的语义名称，Codex 应先映射到当前真实控制器。

## 1. 不把四件事合成一个“模式”

| 维度 | 示例状态 | 切换权限 |
|---|---|---|
| 显示 | Blocks、任务时间线、原始终端只读、原始终端输入、Reader、Review | 查看某种内容本身不授予写权 |
| 草稿意图 | automatic、command、ai；另有解析结果 | 只有显式提交才产生操作 |
| 任务阶段 | idle、thinking、reviewing、awaitingApproval、executing、paused、failed | 由现有任务控制器维护 |
| 写入授权 | none、human、approved_agent_operation | 由现有 lease/guard/revision/operation 检查维护；不是由 UI 布尔值直接授权 |

`connection=connected` 不等于 Shell ready；Shell ready 不等于上一命令成功；AI 结束不等于终端命令结束；页面关闭不天然等于取消。用户可见文案必须与事实一致。

### 输入权是操作级授权，不是永久 Agent 通行证

AI 即使处于 executing，也只能通过当前有效提案/Smart 审阅得到的单次授权写入。任何显示切换、模型输出、task id 相同、native permission event 或旧批准按钮都不能独自授予下一次写入。沿用项目现有会话、节点、cwd、租约、输入代数、proposal revision 校验。

## 2. 动作合同表

| 用户动作 | 草稿/显示结果 | 模型请求 | 有效命令提交 | 写入权变化 |
|---|---|---|---|---|
| 点失败块 AI 诊断 | 附上下文；空稿填诊断问题，有稿不覆盖 | 无 | 无 | 无 |
| 删除来源 Chip | 只移除指定来源；不自动改成命令意图 | 无 | 无 | 无 |
| 采用补全/历史 | 只更新当前草稿 revision | 无 | 无 | 无 |
| 完成展开编辑 | 保存本地草稿和选区 | 无 | 无 | 无 |
| 显式发送 AI | 冻结本轮稿/来源；进入 AI 任务 | 按现有流程一次起始请求；后续推理按正常循环 | 无隐式提交 | 无自动写入授权 |
| 显式执行手工命令 | 当前可见意图是 command，且 shell 条件有效 | 无 | 最多一次有效提交 | 沿用 guarded human submit |
| 审阅命令/看完整输出 | 打开可读页面 | 无 | 无 | 无 |
| 编辑提案并保存 | 新 revision；旧批准失效 | 按既有 Smart 审阅策略可发独立审阅请求 | 无 | 不继承旧批准 |
| 批准一次 | 再验证目标和 revision | 审阅后续由现有机制决定 | 同 operation 最多一次有效提交 | 只授权该操作 |
| 查看终端（只读） | 换显示；保留任务和阅读位置 | 原任务可继续，切换本身不新增请求 | 切换本身无提交 | 无；不能连上可写 input sink |
| 暂停 AI | 停后续推理/排队操作；任务保留 | 取消相关请求 | 不新增提交 | 撤销 Agent 后续写入，不发 Ctrl+C |
| 接管输入 | 先暂停/撤销，再交还人工输入 | 取消相关请求 | 接管本身不提交草稿 | 交还 human owner；不发 Ctrl+C |
| 中断命令 | 明确标示目标命令；等待实际状态 | 不因中断创建新推理 | 不重提原命令 | 有效 human 控制路径显式发送中断 |
| 继续任务 | 刷新真实上下文与原回执，再继续规划 | 可以 | 不重放历史提交 | 新提案仍按原策略审阅 |
| 返回上一阅读位置 | 定位保存锚点，不弹键盘 | 无 | 无 | 无 |

模型 API 在一次任务中可能有多轮 HTTP 请求；“一次发送”只约束用户起始事件不被重复触发，不限制正常多轮推理。

## 3. 只读终端的完成条件

只隐藏软键盘、设置 `readOnly=true` 或禁用 TextField 不够。必须审计所有写入来源：硬件键盘、软件键盘、粘贴、手势、鼠标报告、快捷键桥、自动恢复焦点和延迟回调。只读视图只能持有读取/选择能力，不能通过旧 focus node 或保留 closure 调到 PTY 写入路径。

进入只读页前，终止尚未完成的人工编辑提交意图，不能把 composing 文本当确认提交；不丢掉本地草稿。系统 IME 候选被收起不意味着提交一条命令。离开只读页也不恢复以前的可写焦点；仅明确“接管输入”才进入可写 raw terminal。

**计数口径：** `observer_input_write_count == 0`；不是“整个 PTY 在这段时间绝无字节”。AI 获批动作、远端输出以及终端核心必要的协议应答仍可能存在。测试按来源/operation 归因，不能把核心协议应答算成只读 UI 越权，也不能给越权写入换来源标签以通过测试。

只读观察不应触发新的焦点报告、鼠标报告或 UI 产生的按键。终端核心本来对远端查询作出的协议回应仍由原运行时负责；不要为了界面只读而破坏协议兼容。

## 4. 提交与回执：必须使用正确的“只执行一次”口径

一次命令提交可能包含私有通道准备、唤醒、多个底层 write 或协议帧。验收口径是 `accepted_operations[operation_id] <= 1` / `accepted_submissions[submission_id] <= 1`，以及 fixture 的实际副作用最多发生一次，**不是系统调用 write 的次数必须等于 1**。

同一 operation id 的再次查询/重复工具请求返回已有结果，参数不同则拒绝。未收到确认不能当作未执行。存在 unknown 时主动作是检查原提交；恢复页面、重连、继续任务、晚到的模型结果均不得自动分配新 id 重试原操作。

若连接/进程丢失后客观上无法确认原执行结果，保留“不确定”，不要为让流程继续而重置成 ready。真正需要用户再次执行时，应由用户基于当前状态显式形成新的、可辨的新操作，而非后台自动重试。

## 5. 版本与异步回调的检查点

| 回调/事件 | 必须核对的归属 | 失效处理 |
|---|---|---|
| 补全/历史查询返回 | session、context、editor revision、query identity | 丢弃旧结果，不覆盖新稿 |
| AI 响应返回 | task、connection/config identity、turn generation | 不绑定到新任务；保留可追溯失败 |
| 批准按钮回调 | task、operation、proposal revision、current target guard | 拒绝并提示重新审阅 |
| 开始提交之前 | 当前 node/lease/readiness/manual input generation | fail closed，不偷偷改目标 |
| 接收提交回执 | 原 submission id 与编辑版本 | 只清理原稿；新稿原样保留 |
| 原生 cwd 通知 | 被接受 Block + 同 session/node | 仅沿用已存在的受控目录推进例外 |
| 显式接管 | 任务 generation 与当前 owner | 先撤销排队写；延迟写回调必须失效 |
| Reader 分页返回 | source session、block identity、保留范围/宽度版本 | 失效页不拼到新输出；明确需重新读取 |
| 旋转/布局后的恢复 | 当前 task/view generation、稳定 block/row anchor | 不抢到已切走的 pane；被淘汰时明确降级 |

日志不应暴露真实提示词、用户命令和凭据。调试 fixture 可以记录公开的命令摘要及受控标识。不是要求新增线上遥测服务。

## 6. 草稿、焦点和阅读锚点

每个活动 pane 只呈现一个主编辑入口，但允许底层保留成熟的 Composer controller 与 AI draft controller。通过 adapter 绑定当前 owner，不逐帧把文本盲同步给两者。Reader / Review 关闭默认回到阅读，不能因“上一焦点是输入框”就自动弹键盘。

用稳定语义锚点（来源会话、Block/entry id、原始行或项内偏移）优先于裸 scroll offset。相同字号/宽度下返回允许最多一行偏差；宽度变化或淘汰时记录降级原因，优先恢复同一语义行，不承诺无法成立的像素坐标不变。

手机软键盘 Return 用于换行；硬件键盘快捷键按 S2 表实施。IME composing 优先级高于应用 Enter/Tab/方向键。展开编辑的“完成”只是保存草稿。Esc 按候选 → 当前编辑层/对话框 → 外层导航顺序处理，不能越层取消任务。

## 7. 产品状态优先级与可恢复性

结果未知/执行目标变化/连接不可用优先于待审批，待审批优先于一般运行状态，补全 loading 优先级最低。不能让“自动建议已打开”的临时提示覆盖“此命令可能已执行”。

若未知与断连同时发生，同时保留两个事实：连接无法读取 + 原操作结果未确定。不要用错误码整页替换导致原操作身份和检查入口丢失。

为每个失败状态说明：用户现在能做什么、不能做什么、操作是否可能已发生、能否恢复草稿/上下文。只有真实产品错误提示，不显示测试 harness 内部异常或敏感 provider response body。

## 8. 文档判定与代码审查

本文件对应既有 S1-R02～R11、S2-R01～R06/R09/R12、S3-R03/R05；并由 S1-T04/T05/T06/T08/T09、S2-T03/T10、S4-T05/T06/T09 等覆盖。Codex 不得为新增状态表重写整个运行时；如最新代码已满足，补测试与证据即可。

一项安全断言必须同时有生产调用点、边界测试和运行证据。测试中调用伪 runtime 可以证明 controller 决策，但不能替代实际 App→SSH→原生 Block 的端到端验证。
