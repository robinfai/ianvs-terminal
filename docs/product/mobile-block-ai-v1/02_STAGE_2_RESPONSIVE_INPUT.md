# S2 PRD · 输入、键盘与响应式布局

**阶段目标：** 用户不需要猜输入归属，不因键盘、旋转或阅读长输出丢失操作上下文。  
**依赖：** S1 状态和写入边界已明确；可在 S1 证据待补时做不依赖的组件工作，但不得越级声称验收通过。  
**非目标：** 手机 Dynamic Type、新的远端补全 provider、重写 Shell readline。

## 1. 用户故事与成功标准

手机用户可以编辑真实多行命令或自然语言要求，看见当前输入是“发给 AI”还是“交给 Shell”。软键盘确认汉字绝不会提交；从输出阅读器回来草稿仍在；横屏时不把按钮和字体缩到不可用。

规定 fixture 下，旋转前后草稿字符串、选区及待发送来源完全一致；键盘弹出不改变已完成块的六行预览规则；外部列表锚点误差不超过一行。所有可执行操作须有显式可见入口，不能仅靠长按或外接键盘快捷键。

## 2. 布局区域及优先级

从上到下：单层会话导航 → 内容区 → 必要任务状态 → 统一输入容器 → 当前输入所属工具栏/系统键盘。键盘出现时首先隐藏低频辅助项，不隐藏提交去向、有效目标和主操作，不缩小触控区。

普通命令与 AI 可以共用一个视觉容器、统一 label 和主动作决策；**不要求合并安全不同的 controller 或向两个 controller 同步盲写字符串**。使用显式 adapter/绑定，不把文本变更事件当执行授权。

## 3. 详细需求

### S2-R01 · 单一主输入呈现（P1）

每个活动 pane 只出现一个可写的主输入框；原始终端/TUI 接管时明确显示“终端输入”，不另留一个看似可执行的 Composer。任务和命令的内存草稿按稳定 Session/Task 标识隔离；切换呈现不复制到另一执行目标。

S2 可以以现有 Composer / AI 输入框共享外壳实现，保留各自成熟的编辑能力，禁止为了统一外观丢掉补全、历史、undo、灰字或租约校验。

### S2-R02 · Auto / Command / AI 的可预测行为（P0）

菜单三项：自动识别、命令、AI。选择后立即显示当前解析结果，例如 `自动 · 命令` 或 `自动 · AI`；主按钮同步为“执行”或“发送给 AI”。忙碌时是“补充要求”，不会把补充文字写入 Shell。

沿用现有 evidence-first 输入识别，只有可信命令证据/明确命令选择才执行；含糊文字安全地走 AI 或等待用户选择，不能靠较低 AI 分数推断允许执行。提交使用点击瞬间的草稿 revision 与可见意图，禁止异步分类返回后换目标执行。

显式手选优先于自动识别；只作用于当前上下文。附带 Block 来源时 Command 不可直接启用，必须先移除来源或明确开启独立命令草稿。

### S2-R03 · 手机多行编辑（P1）

竖屏主输入默认 1 行，按实际行高增长至 4 行，再内部滚动。单行中文、英文和 emoji 使用一致固定行高，不能切换内容就抖高。输入高度上限是内容区实际约束；极短窗口走 S2-R04。

长命令在主列表标题显示至多两行，完整值在 Reader / 审阅页可读。草稿复制不含灰字；中间 token 补全不能覆盖右侧参数；undo/redo、选择、中文路径、转义和换行保持原始字符串。

### S2-R04 · 展开编辑与短窗口（P1）

提供 `展开编辑` 明确按钮。全屏编辑页有完整草稿、显式输入去向、可滚动编辑器、取消和“完成编辑”。完成只保存草稿，不执行；取消恢复进入时原稿与选区。软键盘 Return 在该页始终换行。

可用内容高度 < 200 逻辑像素时，采用单行紧凑编辑+主操作，提供触控可达的展开/收键盘。可用高度连一排 44 点控件都容不下时，优先收键盘或进入全屏编辑，而不是溢出或隐藏关闭入口。横屏审批仍可全屏查看与滚动，不能因操作区挤占而遮住全部命令。

### S2-R05 · IME 与键盘合同（P0）

| 场景 | 键位 / 操作 | 行为 |
|---|---|---|
| 手机软件键盘的 Return | 正常编辑 | 换行；执行/发送使用显式按钮 |
| 系统 IME composing | Enter / Tab / 方向键 | 先交输入法；不提交、不采用应用候选 |
| 外接键盘 Command 输入 | Enter | 有候选时仅采用，无候选且条件满足才执行 |
| 外接键盘 AI 输入 | Enter / Shift+Enter | 发送 / 换行；composing 时不发送 |
| 外接键盘 Command 输入 | Shift+Enter | 换行，保留现有其他平台换行键位 |
| 任何编辑场景 | Esc | 先取消应用候选/历史，再关当前编辑层；不越层取消任务 |
| Raw Terminal / TUI | Ctrl+C / Esc 等 | 只有当前 write owner 可发送真实终端键 |

系统软键盘与外接键盘分开测试。不能把 `controller.value.composing` 人工赋值测试当作真实中文输入法通过。

### S2-R06 · 键盘与视口稳定（P1）

基于当前 constraints、safe area 和真实 viewInsets 计算，不按机型名称硬编码。已完成 Block 六行规则独立于键盘高度。键盘开关只改变列表可视高度，不能不断压缩块导致阅读锚点漂移。

打开 Reader 和审批页先收键盘；普通返回默认保持阅读、不自动弹出，只有用户点输入才再显示。AI 流式结果到来不抢焦点。原始终端真实 viewport 改变才允许已有 resize 路径更新 PTY；仅打开只读 AI 覆盖层不重设 PTY 几何。旋转产生合法重排时，按原生稳定身份恢复块，不按旧像素偏移盲定位。

### S2-R07 · 长命令、目标信息与文字（P1）

会话标题单行且详情可达；命令标题两行；执行目标不能只剩模糊省略号。审批页主机/节点/cwd 可换行和选择。中文文案与代码分别使用语义字体；代码保持等宽。手机固定 UI 字号，已有用户主动的终端字体缩放功能不得被全局 clamp 误删。

### S2-R08 · Reader 与错误定位（P1）

保持原生分页阅读器与单一纵向滚动。默认预览依旧末尾六行；错误可能在前面，因此提供“查找错误/在此块搜索”的便捷入口，不把末尾六行称为完整诊断。

默认不新增自动 AI 摘要。可用既有搜索定位错误关键词，但须标明“匹配行”而非模型事实。显示原始行范围、总保留行数和淘汰提示；返回主列表保持原位置。复制“全部”指全部仍保留输出，受原有上限约束，不得暗示已淘汰数据可恢复。

### S2-R09 · 来源 Chips（P0）

主输入显示来源摘要；多来源横向单行滚动，至少一个显示计数与详情入口。删除动作命中区独立，不触发来源跳转。短窗用可见计数按钮进入列表；从详情返回不丢草稿。发送时冻结每个来源与范围，不把今天的新输出绑定旧问题。

### S2-R10 · 触控与辅助输入（P1）

所有主要移动操作触控命中区至少 44×44 逻辑点；图标可以小，但命中区不能小。已有文字长按选择优先，不同时弹两层菜单。主列表滚动与 Reader 滚动不嵌套争夺；运行块的输入通道与完成块只读选择区别明确。

Block 菜单保留完整能力，主界面只露出当前情境关键动作。Swipe/长按可以增强，但任何能力均有普通点击入口。硬件键盘焦点顺序：会话 → 内容/待审批 → 输入去向 → 编辑器 → 主动作；桌面保留原有习惯。

### S2-R11 · iPad 双栏（P1）

建议可用宽度 ≥ 960、高度 ≥ 600 逻辑点且两栏各 ≥ 360 时启用双栏：左侧任务时间线，右侧只读终端/输出；否则退回单栏。阈值是本轮设计起点，可据实测作有记录的调整。

两栏属于同一 Session/Task，不创建新 PTY；只读终端仍不能发送按键和鼠标报告。分栏收放保持草稿、来源、阅读锚点和审批版本。split view / 窗口 resize 以实际约束驱动，不仅判断平台是 iPad。

### S2-R12 · 桌面回归（P0）

保留桌面三层 Dock、Tab 采用、真实 Shell 历史、灰字、分屏、raw 回退和代码等宽。S2 的移动 Return 行为不可污染桌面快捷键。`terminal_ai_workspace.dart` 可拆 view 组件，但不能重造 runtime。

## 4. 布局状态矩阵

| 状态 | 信息优先级 | 输入规则 |
|---|---|---|
| 手机竖屏、无键盘 | 主机/内容/状态/编辑器 | 1–4 行，可展开 |
| 手机竖屏、有键盘 | 内容 + 去向 + 主动作 | 非关键工具可收拢，块不压缩 |
| 手机横屏、有键盘 | 去向/草稿/主动作/收键盘 | 极短时单行或全屏编辑 |
| 全屏 Reader | 原始输出/查找/返回 | 不写 PTY，不自动恢复键盘 |
| 全屏审批 | 目标/完整命令/固定批准区 | 不复用主 Composer 的发送动作 |
| iPad 宽窗口 | 任务 + 只读终端 | 一套写入所有权 |
| iPad 窄窗口 | 单栏 | 与手机相似但不强制手机字号策略 |

## 6. 实施落点

优先 `terminal_ai_workspace.dart` 的 prompt/composer 与 `terminal_composer_view.dart` 的公共呈现决策；移动导航和输入在 `shell_screen_mobile_navigation.dart`、`shell_screen_mobile_input.dart` 及 iOS 输入栏。Reader 沿用 `command_blocks_compact.dart` / `command_block_reader.dart`，不要另写 WebView 阅读器。平台差异收口到 adapter 与 tokens，避免散落数十个 isIOS 条件。

## 8. 退出条件

S2 十二用例通过，无 overflow、无误提交、无焦点抢占；保存 before/after 同环境画面及旋转/IME/阅读录屏。真实中文键盘模拟器验证可作为阶段证据，S4 仍必须用实机重跑。
