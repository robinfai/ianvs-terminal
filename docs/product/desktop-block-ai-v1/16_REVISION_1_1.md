# 16 · v1.1 交互修订

2026-10-10。依据本轮 PRD 交互评审收敛实现语义；不是产品验收结论。以下条款覆盖 v1.0 中同一动作的歧义，其他 64 条需求、平台范围、原生证据和完整 gate 不变。原包及校验清单见 [来源身份](SOURCE_ARCHIVE.json) 与 [原始校验清单](SOURCE_SHA256SUMS.txt)。

## RV-01 · 审批档位

保留现有 Manual / Smart 及谨慎、标准、宽松三档。Manual 每次明确确认；Smart 对当前操作独立审核，谨慎只自动放行低风险，标准和宽松按现有策略判断，宽松允许符合目标的低／中风险操作自动执行，高风险、未知风险、授权不清、审核失败仍需确认。准确策略与迁移规则以现有 [Smart 审批说明](../../ai/SMART_APPROVAL.md) 为准，不能借桌面重构降低已经交付的自动化程度。

原因区分手工模式、所选档位、高风险／授权不清、审核不可用。保存配置不发模型、不执行；切档撤销旧审核。D4-T05 在 API 和 ACP 上分别覆盖三档、迟到结论、失败降级和人工编辑。

## RV-02 · 补充要求

| 收到要求时 | 旧操作 | 新要求 |
|---|---|---|
| 分析／独立审核中 | 取消旧请求，晚到结论无效 | 按新要求重新规划 |
| 等待批准 | 撤销旧提案，保留失效记录 | 按新要求重新规划 |
| 已发送且回执已确认 | 命令可能仍运行；不发送 Ctrl+C | 读取当前事实后规划，禁止默认重发 |
| 正在提交／结果未知 | 保留原 submission、目标和未知事实 | 保存为明确“尚未发送”的要求，暂停新推理与写入 |

未知状态下已接收的补充要求显示在本任务记录中，并冻结当时选择的来源。仅检查回执不发送要求；确认原回执后，用户明确继续／发送才将保存的要求交给模型，不能用通用“继续任务”悄悄跳过。用户可以明确移除未发送要求，记录保留为已撤销。新草稿不被迟到结果清空。暂存内容受原有请求／上下文预算限制；超过限制保留草稿并说明原因。

D1-T04 必须覆盖以上每一阶段，同时断言模型请求、有效提交计数、旧按钮失效和历史可追溯。

## RV-03 · 收起、暂停、输入权和等待

| 入口／事件 | 行为 |
|---|---|
| 任务层 Esc、关闭／收起、顶部 AI 切换 | 进入只读观察，保留任务和有效等待提案；原任务可按已有策略继续 |
| 暂停 AI | 取消后续规划／审核／未提交操作；不发 Ctrl+C |
| 接管输入 | 先撤销 Agent 后续写入，再把人工输入权交给对应终端；本身不提交草稿 |
| 中断命令 | 用户对当前目标明确发送中断，结果由真实终端确认 |
| 切 pane／tab／window | 不重定向任务；非活动处不能批准或接收人工输入，返回先重读目标 |
| 切 task | 撤销旧 task 尚未执行的授权；保留草稿、记录、来源与阅读锚点 |
| 仅经过时间 | 等待的命令提案不因墙钟时间失效 |
| 实际目标、lease、人工输入或配置变化 | 按既有 guard 撤销旧授权，保留可查看的旧文本 |

Esc 优先退出最内层菜单／审阅／Reader；不能穿透给 TUI。手机退后台仍遵守移动生命周期保护，所有保留 controller 都必须收到事件，而不只依赖当前可见页面。手机恢复、桌面 sleep/wake 与仅切窗口须分别验证，不能互相代替。

D1-T10、D1-T13、D4-T10 增加入口与生命周期状态表，分别验证“文本保留、提案有效、允许批准、AI 是否继续”；恢复本身零执行。

## RV-04 · 人工编辑提案

保存只创建新 revision；旧文本作为已撤销版本保留，新版本清除旧审核结论。即使处于 Smart 模式，人工编辑后的保存也不自动请求审核或执行。用户在完整审阅当前目标和新命令后明确“执行一次”。正常新提案仍可按 Smart 当前档位自动审核，不改变该通道。

D1-T07 与 D4-T05 断言：保存零提交，旧 revision 和晚到审核无效，新 revision 只执行一次，审计记录同时保留旧／新文本。

## RV-05 · 未知结果的终止出口

检查原回执可能得到：已确认接收／拒绝、仍运行、暂时未知、原会话不可恢复。不能把连接到新 Session 当作原命令成功，也不能以“继续”创建新 ID 重发。

持续未知时提供“结束跟进”。这个动作结束本 task 的 AI 跟进，不中断远端进程，不把未知改成失败／成功／未执行。旧 task 保留为只读记录，仍可检查原回执；后续出现可靠回执可更新事实，但不复活任务。用户可明确新建任务，新任务不复制旧待执行命令、不继承旧授权，第一次请求重新读取当前目标。新任务也不能绕过原有 shell readiness、lease 与目标校验。

D1-T11、D4-T10 覆盖服务端已有副作用、客户端永久无法取得回执的情况；结束跟进和新建任务均不得重发旧操作。

原静态设计稿作为 v1.0 历史参考保留。浅色辅助文字的静态 CSS 组合未满足本包 4.5:1 目标，实现使用经过核对的生产主题 token；不能把静态图当真实 App、IME、VoiceOver 或缩放证据。
