# 09 · 完成后的 GitHub 独立复核手册

## 1. 先确定审的版本

通过GitHub读取用户指定分支/PR的最新HEAD；记录评审HEAD R、提交人声明的实现C与证据E。不能默认仍是PRD编写基线。检查PR/compare/changed files，确认E相对C只包含合法文档证据；若R在E之后又改产品、测试驱动或构建依赖，标证据陈旧并要求重跑影响面。

入口：本目录STATUS、results/BASELINE、D1…D4、FINAL_REVIEW、PLATFORM_MATRIX、PERFORMANCE、evidence/manifest.json。找不到入口不是自动失败所有代码，但属于交付证据缺失；列精确缺文件，不凭完成回复猜内容。

## 2. 逐需求核查，不只看任务勾选

对64条需求先区分保留能力、新增实现、测试/证据补齐。顺着生产装配查真实调用：菜单/键位→view/controller→guard/runtime→nativePTY→receipt/Block；不能只在preview或测试假runtime里出现。

高风险必看：只读sink所有入口、同operation幂等、编辑后revision、错目标、手动接管竞态、unknown恢复、后台焦点、多个pane共享状态、TUI几何、API/ACP实际权限边界。类名或注释声称安全不算证明。历史已修复缺陷不得因为旧PRD又判成新问题。

## 3. 图像与录屏实查

打开真实PNG，不仅确认路径存在。按159个检查点核对内容，确认图中主机/pane、输入意图、状态、命令、退出码与日志一致。核对capture class与构建环境，不把HTML/Widget/桌面窄窗称为其他平台实机。

对动态场景看连续视频关键过程：IME确认→仍未发送、内外滚动边界、tab切换→焦点保留、只读尝试→无写入、重复批准→一次有效operation。原图尺寸/哈希只证明文件一致，不证明内容真实；发现设计稿当证据为P0交付诚信缺陷。

## 4. 测试与环境

读取实际测试源码与原始日志，查负向断言、有效target/lease使用、异常分支与副作用计数。mock只验证接线/状态机；真实API/ACP/SSH/原生PTY各有独立记录。make verify失败不能被只贴test-composer通过覆盖。

无法在评审环境运行macOS或真实模型时，明确本轮是代码/已提交证据复核而非重新实测；可以判断缺证据/逻辑错误，不能宣称亲自验证设备。Linux/Windows主机目录存在不能判可用，按13分平台审。

## 5. 版本新鲜度

默认最终自动gate要求最终C4截图/视频/日志。旧证据复用必须人工核对依赖闭包hash、锁文件、native库、主题/字体、测试驱动与环境，明确复用范围；有任何未映射影响直接重跑。源码附近“没改逻辑”不是完整依赖分析。

从GitHub取回清单及证据后运行：

```sh
python3 scripts/validate_evidence.py evidence/manifest.json --gate final
```

该工具不下载远程凭据资源、不自动执行仓库命令。平台扩展证据、源码真实性和物理设备声明仍需人审。

## 6. 审查输出格式

结论按D1–D4分别为通过/有条件通过/未验证/失败，并注明macOS与其他桌面的实际范围。

|严重度|需求/用例|生产代码路径与行|图/日志证据|可复现步骤|期望与实际|最小修复|重测范围|
|---|---|---|---|---|---|---|---|
|待填写|D?-R?? / D?-T??|实际commit链接|实际路径|具体操作|差异|不重写无关代码|受影响case|

P0：错目标/越权/重复执行、秘密泄露、伪证据；P1：核心动作不可达、IME误触发、阅读/草稿丢失、重要平台/模型证据缺失；P2：非阻断视觉/效率问题。证据不足要标缺验证，不能凭静态图武断说产品有某个运行bug。

## 7. 最终接受条件

零开放P0/核心P1；64case证据与依赖新鲜；真实物理/模型/平台范围符合声明；完整gate可核对；UI稿差异有依据；状态文案不夸大；数据/持久化边界不变。macOS可单独验收，不能把未验证Linux/Windows一起打勾。

需要返工时给最小补丁范围、重测case、必须重拍的shot id，保留通过项，避免每轮全部推倒。
