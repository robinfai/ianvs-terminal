# D1 PRD · 桌面 Block × AI 工作流

> 2026-10-10 修订：与本文有关的敏感性、补充要求、收起/Esc、人工编辑保存和未知结果出口，统一以 [v1.1 交互修订](16_REVISION_1_1.md) 为准。原有 64 项需求及全部原生验收门槛保留。


**目标：**在桌面完成一条可理解、可审阅、可回溯的 Block × AI 链路，同时保留传统命令效率。

**依赖：**先读取00、11，核对当前入口、任务与审批生产路径。

**非目标：**不重写终端核心，不引入永久侧栏、自动执行诊断或新远程Agent。

## 1. 用户故事与交付判断

作为桌面开发者，我想直接从命令输出获得AI帮助，知道它准备在什么主机/目录做什么；批准后从原生Block看到结果，随时只读查看或明确接管。核心路径不能靠反复复制日志，也不能为了少一步而隐式执行。

本阶段每项需求均有独立case，表中步骤还须拆出其中包含的负向子场景。已有能力满足则补回归，不重复开发。所有“应/必须”为验收要求，不是本轮已完成声明。

## 2. 逐条需求

### D1-R01 · 桌面壳与任务入口（P1）

**必须行为：**保留一层窗口顶栏：窗口控制、Terminal tabs、增加 tab 与既有必要入口同层；底部状态栏继续存在。默认主内容仍是终端与 pane-local 三层 Composer Dock，不新增永久项目侧栏、第二条全局导航或新的 Project Workspace。AI 从当前 pane 的明确入口进入。

**边界与实现：**会话、显示形式、输入意图与 AI 任务是不同对象。进入 AI 不创建第二个 PTY，不改变 Profile/Layout/Recording 的持久化边界；已有用户配置的布局不因这轮优化重置。

**验收：**`D1-T01`。进入/返回不重建 Shell；目标始终可见；任务区域关闭后原草稿和终端仍在。

### D1-R02 · Block 情境操作与失败诊断（P1）

**必须行为：**失败且已完成的 Block 常驻文字按钮“AI 诊断”；成功块在选中/键盘聚焦时显示“询问 AI、复制、放入编辑”等情境动作，hover 可增强但不是唯一入口。右键与省略号菜单保留完整原有能力。

**边界与实现：**“AI 诊断”只附加来源并准备草稿，零起始模型请求、零用户命令提交；已有草稿不覆盖，提供插入问题。不得用“重跑”命名仅放回编辑的行为；本轮默认复用是放入编辑，不即刻执行。

**验收：**`D1-T02`。诊断一步可达且未执行；运行中块不能被“纠正”自动重跑；正常块没有一排永久高噪音按钮。

### D1-R03 · 选择上下文及来源冻结（P0）

**必须行为：**支持现有单块、多块与行范围附加；用 sourceSessionId、blockId、范围、保留/截断信息组成来源。默认附加当前明确选择，不悄悄换成“最新块”。发送后来源冻结，结果引用只认该次真正提供的证据。

**边界与实现：**选择多个块按当前时间线顺序去重；不同会话同 blockId 不混用。跨会话来源仅沿用当前已支持的保留连接阅读路径，不新增任意多主机执行/上传功能；默认新选择限当前任务绑定的会话。

**验收：**`D1-T03`。剩余来源、范围与顺序准确；截断明确；旧回复不因新命令产生而改绑证据。

### D1-R04 · 单一可写入口与明确路由（P0）

**必须行为：**同一活动 pane、同一工作视图只呈现一个可写主编辑器。普通终端沿用 Composer；任务视图使用兼容的公共输入外壳，支持 Auto/Command/AI 可见去向。主按钮分别“采用、执行、发送给 AI、补充要求”，而不是一枚含糊箭头。

**边界与实现：**可保留不同 controller，通过 adapter 绑定，不逐帧复制文本给两个执行通道。显式手选优先；提交冻结可见意图和草稿 revision；附来源/AI 忙时不得将文字路由成 Shell 命令。未知识别不得当作执行授权。

**验收：**`D1-T04`。点击时看到的去向即执行去向；普通手工命令零推理；未提交的模式切换零写入。

### D1-R05 · 任务时间线与真实执行证据（P1）

**必须行为：**按用户意图、AI 解释、待审操作、原生命令结果、总结分层呈现；命令执行事实继续通过 CommandBlockTimelineItem 的稳定引用显示。完成步骤可紧凑分组，展开仍定位原 Block，不保存一份新日志副本。

**边界与实现：**AI 声称完成不代表命令成功。没有可信退出码不画成功勾；失效引用显示不可用，不补猜测链接。大段输出继续原生分页；运行块不自动折叠，用户正在阅读的组不被新消息自动收起。

**验收：**`D1-T05`。准确显示真实 2 成功/1 失败，而非全绿；不重复终端日志；引用可回到原数据。

### D1-R06 · 桌面完整命令审阅（P0）

**必须行为：**桌面优先在当前 pane 展开审阅；长命令或窄 pane 提供有标题、可调整内容空间的审阅层，不强制照搬手机全屏页。目的、主机/SSH 节点/cwd、审阅原因、完整命令和“拒绝/编辑/执行一次”必须清楚。

**边界与实现：**只有当前审阅 surface 能提供完整命令且目标未变时可批准；任何摘要、折叠、截断三行卡均只提供“审阅完整命令”。完整不等于要求滚到底解锁；不能用滚动位置充当安全保证。弹层冻结 target，不跟随用户点另一个 pane 自动换目标。

**验收：**`D1-T06`。完整内容可读可复制；副作用字节不被视觉折行改变；切走目标后旧批准不可执行。

### D1-R07 · 编辑提案与审批版本（P0）

**必须行为：**编辑保存创建新 proposal revision；保留旧版本为已失效记录，新版本明确显示“需重新审阅”。编辑器复制/撤销/换行正常，保存不是执行。Smart 模式按既有审阅流程重新判断，不复用旧结论。

**边界与实现：**旧审阅层、延迟按钮回调、模型补充文字都不能批准新版本；同一 task 切换连接/目标也使旧授权不可用。命令 diff 是辅助，可用原始全文核对，不用 diff 代替最终执行内容。

**验收：**`D1-T07`。A 零提交；B 使用新 revision/guard；保存操作不会执行。

### D1-R08 · 提交、连点与执行回执（P0）

**必须行为：**批准一次或执行手工命令均复用现有 lease/guard/submission/operation 机制。提交中禁用同一操作；通过原回执过渡到运行/完成状态，不把“输入已接收”画成成功。

**边界与实现：**一次有效命令可能包含多次底层 write/唤醒帧；验收 accepted_operations[id]≤1 与 fixture 副作用计数≤1，而非 write syscall 恰好一次。迟到 accepted 只能清理原 editor revision，不能清空后写的新草稿。

**验收：**`D1-T08`。只有一次有效操作；新稿保留；submitted、running、finished 的显示依据可追溯。

### D1-R09 · 只读观察终端（P0）

**必须行为：**提供“查看终端（只读）”，只换显示，不调用 takeOver，不授予 write sink，不改变任务绑定。鼠标选择/复制可用；任何键盘、粘贴、文件拖入、焦点报告及鼠标报告不能由 observer UI 产生写入。

**边界与实现：**可先复用同 pane 的只读查看；并排观察仅在现有布局或后续 D2 明确规则下启用。保留核心对远端查询的必要协议应答；按写入来源计数，不能把正常协议应答算成人工越权。

**验收：**`D1-T09`。observer_input_write_count=0；任务不因查看而暂停；复制有效，核心协议兼容不受破坏。

### D1-R10 · 暂停、接管与中断分离（P0）

**必须行为：**“暂停 AI”停止后续推理/排队动作，不中断已经运行的命令；“接管输入”先撤销 Agent 后续写再把 human owner 交给 raw terminal；“中断命令”是单独的作用于明确目标的操作。

**边界与实现：**不得简单删除所有 takeOver 调用以实现“收起”。关闭任务视图必须有“收起并只读查看”或“暂停 AI 并返回”的准确文案。已在途写入不能承诺撤回；部分 send_keys 保留 receipt 与已发送步数。

**验收：**`D1-T10`。暂停/接管本身不发 Ctrl+C；接管后迟到写无效；中断结果来自原生观察。

### D1-R11 · 未知回执与故障恢复（P0）

**必须行为：**结果未知持续显示“可能已执行”，保留原 operation/submission 标识和“检查原提交”入口。不能出现自动重发或普通“重试命令”按钮。断连与未知同时存在时保留两个事实。

**边界与实现：**重连/恢复任务先核对原目标与原回执；无法证实时保持未知，不重置为 ready。用户真正想再次执行必须基于当前事实产生显式新操作，并清楚区别于原请求。

**验收：**`D1-T11`。副作用最多一次；只检查旧 id；新提示/补全不覆盖未知警示。

### D1-R12 · 执行目标变化与目录推进（P0）

**必须行为：**任务始终绑定原 Session/SSH 节点；活动 pane 变化不会自动变更执行目标。发生目标变化时显示原/现目标比较，旧提案失效。“在当前目标继续”意为重新观察规划，不是批准旧命令。

**边界与实现：**仅沿用已接受 Block 同 session/node 的可信 cwd 通知例外；不能把任意 OSC、标题、手动 cd 或另一个 pane 的 cwd 作为授权。完整路径可复制和展开，不只露一个省略号。

**验收：**`D1-T12`。前者阻止旧提交；后者仅在既有可信关联下继续；A 的任务不会写 B。

### D1-R13 · 任务、草稿与关闭生命周期（P0）

**必须行为：**按 Session/Task 隔离草稿、来源、选区和阅读锚点。新任务不清空 Shell 历史；返回旧任务不重发提示词。关闭 tab/pane/window 涉及运行命令或未审提案时说明实际后果，并复用既有关闭保护。

**边界与实现：**内存任务不承诺跨进程恢复。取消关闭保留所有状态；确认关闭前允许复制草稿，但不新增云草稿/持久化格式。只有隐藏视图不等于结束 Session。

**验收：**`D1-T13`。草稿不串；取消关闭无损；已关闭 Session 的异步回调不再获得焦点或写入。

### D1-R14 · 模型 API 的连接与错误状态（P1）

**必须行为：**保留 API endpoint/model/key 的当前设置、安全存储和测试流程。未配置时仍允许普通终端；配置保存不发送历史草稿。认证、网络、响应格式错误与 Shell 错误分开呈现。

**边界与实现：**不暴露 API key 或 provider response body；终端输出是模型的不可信输入。真实 API 与 mock 验证分栏记账，模型能力失败不能掩饰为 UI 已通过或反之。

**验收：**`D1-T14`。错误可恢复且不删执行证据；保存零任务请求；普通手工命令不依赖模型配置。

### D1-R15 · 桌面 ACP 设置、恢复与权限（P0）

**必须行为：**将本地 Codex ACP 作为桌面一等入口，与模型 API 分开显示后端/模型。自动检测、手动可执行路径和参数、测试连接、保存及恢复任务遵守当前实现；Finder 最小 PATH 是独立验收。

**边界与实现：**本 PRD 不固定未来模型版本，以当前实际可用配置为准。不能自动安装适配器、发起登录、扩开 native shell/file tools 或远程 ACP。连接不变保存保留任务；更换涉及 ACP 的连接不悄悄沿用旧授权；UI 权限事件不替代宿主审批。

**验收：**`D1-T15`。后端与实际模型可核对；无隐式安装/任务执行；恢复不重放操作；旧任务仍可读但不向替换后端偷发。

### D1-R16 · AI 与 Raw/TUI 的同会话闭环（P0）

**必须行为：**同一 Session 支持 Block 任务与完整原始终端回退。vim/top 等交互程序使用实际终端几何和输入协议；退出只提供手动恢复 Blocks。AI 结论引用终端观察，不把截断预览当全屏程序状态。

**边界与实现：**不新增第二套 parser、PTY、Agent execution loop。AI 覆盖层开合不得无意 resize 底层 TUI；真的调整布局走原有 resize 协调。未知、目标失效和接管保护在 TUI 路径同样有效。

**验收：**`D1-T16`。程序可操作且显示完整；退出不抢回模式；Block/AI/PTY 身份连续且无重发。
