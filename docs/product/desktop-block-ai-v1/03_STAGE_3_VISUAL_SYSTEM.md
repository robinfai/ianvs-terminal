# D3 PRD · 桌面视觉系统与无障碍

**目标：**统一桌面视觉层级和状态语义；保留现有三层Dock、原生外壳及主题选择。

**依赖：**D1行为和D2布局稳定；已有设计方案1是保留基线。

**非目标：**不换品牌，不重做完整配置产品，不用截图铺UI，不删旧安全与键盘路径。

## 1. 用户故事与交付判断

作为长时间使用终端的用户，我需要安静、可读且信息密度合理的界面，清楚区分建议、执行事实和不确定状态；浅深色、缩放和辅助技术都不能让关键操作失踪。

本阶段每项需求均有独立case，表中步骤还须拆出其中包含的负向子场景。已有能力满足则补回归，不重复开发。所有“应/必须”为验收要求，不是本轮已完成声明。

## 2. 逐条需求

### D3-R01 · 主题 tokens 盘点与映射（P1）

**必须行为：**复用 AppThemeTokens、ColorScheme、ComposerTheme、Typography与现有图标族。按surface/text/border/action/status/focus/selection建立映射表，明确哪些沿用、哪些新增；颜色跟随应用主题而非固定仿Warp蓝色。

**边界与实现：**生产Widget不散落硬编码色值；不为新界面另造第二套主题管理。静态设计稿色值仅参考，不能从PNG取色当唯一实现依据；新增token必须说明消费组件与深浅色对应。

**验收：**`D3-T01`。同一语义一套来源；主题变化完整生效；无局部固定品牌色。

### D3-R02 · 浅深色、ANSI与选区（P1）

**必须行为：**完整覆盖浅色、深色、高对比；终端ANSI、OSC链接和选区与UI状态颜色区别明确。失败通过小图标/文字/局部动作强调，不整块红底、不左侧色条，不使用AI霓虹/呼吸灯。

**边界与实现：**普通文本对比≥4.5:1，必要非文字控件/焦点提示≥3:1作为本轮验收目标；提交实际组合计算，不声称完整标准认证。ANSI颜色若受用户主题影响，报告配置而不是强制改成品牌色。

**验收：**`D3-T02`。错误与选区可分；代码可读；浅深不是截图滤镜互转。

### D3-R03 · Command Block 桌面密度（P1）

**必须行为：**保持轻分隔的执行记录，不把每块包装成大卡片。标题、输出、退出码/耗时/操作层级明确；默认上限按pane H/3，紧凑模式沿用；selected/hover/focused/running不能用同一种状态外观。

**边界与实现：**完整命令通过展开/Reader可读；状态未知不画成功勾；命令标题和真实输出使用等宽字体。主界面允许留白，不用假建议卡填满终端区域。

**验收：**`D3-T03`。状态区别无需猜颜色；未选块安静；动作不造成块高度反复抖动。

### D3-R04 · 三层 Composer Dock 视觉合同（P1）

**必须行为：**保留环境/目录行、等宽编辑区、操作行三层；补全浮层位于上方，宽窗详情侧置。输入聚焦靠光标及合规焦点语义，不恢复蓝色外框、下划线或左色条。

**边界与实现：**活动pane边框只包终端区域；固定行高使中英emoji单行不抖。发送/运行占位保持编辑前高度；主动作文字不因尺寸变化变成不可辨符号。手工命令与AI外壳一致但语义不混合。

**验收：**`D3-T04`。Dock层级稳定；run/accept/AI动作清晰；无双层重框。

### D3-R05 · AI 内容与执行事实分层（P1）

**必须行为：**用户请求、AI正文、任务步骤、待审操作、原生结果与总结引用分别用文字权重/间距/必要分隔区分。真实输出不改成Markdown代码块；模型代码建议不伪装成已经执行的终端。

**边界与实现：**模型想法不编造成可验证进度百分比，不制造不存在的chain-of-thought。计划可显示简短对用户有意义的步骤；工具记录与消息分组只影响视图，不改变审批范围。

**验收：**`D3-T05`。一眼可分建议与事实；没有重复输出副本；真实退出状态可验证。

### D3-R06 · 状态优先级与准确文案（P0）

**必须行为：**回执未知/目标变化/连接失效高于待审批，高于执行/推理，高于补全反馈。按真实事实显示“正在提交、命令运行中、AI正在分析、AI已暂停但命令仍运行、执行失败”等，不能都叫运行中。

**边界与实现：**多个重要事实可并存；Shell ready≠上一条成功，AI完成≠进程结束，连接在线≠可执行。未知退出码用未知标签；禁止“绝对安全”或无依据百分比。

**验收：**`D3-T06`。高优先信息不被toast覆盖；每状态只出现合法动作。

### D3-R07 · 字体、等宽与字形来源（P1）

**必须行为：**终端字体沿用用户选择与项目回退链；UI使用系统字体，代码独立等宽。检测 iiii/WWWW等长字串实际native宽度；中文、emoji、组合字符和连字不破坏cell选择。

**边界与实现：**不得把测试注册固定字体后的golden当原生字体证明。不得交付系统/容器字体文件；新增第三方字体需明确许可且本轮默认不新增。字号变更需要记录而非缩字硬塞布局。

**验收：**`D3-T07`。真正原生等宽；无裁字、乱码；复制内容准确。

### D3-R08 · 桌面响应式与文字缩放（P1）

**必须行为：**适配标准16:9与用户实际窗口比例；窗口最小尺寸由当前宿主约束决定，不假定只能16:9。桌面文字1/1.5/2检查覆盖Dock、审批、菜单、状态栏及split pane，不继承手机固定字号clamp。

**边界与实现：**先收低频信息，再折行/详情，不先缩字号；长路径/目标必须有可读详情。视口很小时允许摘要+Reader，但不可藏起唯一取消/批准说明。

**验收：**`D3-T08`。没有overflow；关键动作可达；跨端差异不污染手机固定字号规则。

### D3-R09 · Hover、focus、pressed与disabled（P1）

**必须行为：**为Block、ContextChip、候选、按钮、tab和分割条建立状态册。focus有可辨指示；hover不等于selected，pressed不等于已执行；disabled展示原因且读屏可读。

**边界与实现：**图标旁tooltip仅辅助；高风险按钮不能依赖hover才看清目标。不要用组件颜色自动推断执行状态；异步状态变化保留键盘焦点到有意义位置。

**验收：**`D3-T09`。每状态有语义且可分辨；鼠标移出不会丢关键操作。

### D3-R10 · 中英本地化与长路径（P1）

**必须行为：**中英文动作一致：采用、执行、发送给AI、补充要求、审阅完整命令、执行一次、只读查看、接管输入、暂停AI、中断命令。长命令/路径/主机别名支持折行与可复制详情。

**边界与实现：**内部模型/Session id不替代用户友好标签，但诊断详情可带匿名标识；敏感provider响应不能原文泄漏。文案换行不改变命令字节。

**验收：**`D3-T10`。不出现混合语言漏翻译；省略有详情；关键目标不被完全截断。

### D3-R11 · 桌面可访问性与读序（P1）

**必须行为：**支持键盘完成主闭环；控件名称含对象与动作，Block朗读命令/状态但不自动逐行播出流水日志。modal限制焦点在有效范围，关闭回触发点；审批失效读序不会落到已销毁按钮。

**边界与实现：**Semantics树检查只是自动补充；真实macOS VoiceOver与Full Keyboard Access需D4操作证据。菜单与快捷键不能劫持系统/输入法组合；界面不能为了极简抹掉焦点。

**验收：**`D3-T11`。所有核心动作不靠鼠标；状态播报适量且含正确目标。

### D3-R12 · 动效、减少动画与稳定布局（P1）

**必须行为：**普通状态过渡采用短促、克制的宿主动效；建议120–180ms为起点。减少动画时去除位移/弹跳和大面积淡入，内容到达不让整条时间线闪烁；不强制用户等待动画结束才能取消。

**边界与实现：**执行授权不由动画完成回调决定；布局重建不重复触发请求、重新申请焦点或start timer。页面动画退出期间controller生命周期正确，取消/销毁回调可安全忽略。

**验收：**`D3-T12`。无闪屏、跳动、重复请求；动画取消不导致失效controller异常。

### D3-R13 · 来源与证据检查器规范（P0）

**必须行为：**来源Chip显示命令片段、数量/范围、截断标识，点击查看，删除独立。Evidence正文必须能辨认原session/block/行范围；来源已淘汰或失效时准确说明，不假补日志。

**边界与实现：**过多Chip用可访问溢出计数与展开，不横向挤掉主动作。多来源绑定在发送时冻结；只是阅读某个来源不会把执行目标换到该来源主机。

**验收：**`D3-T13`。来源信息完整；删除命中不误跳转；无retarget/自动发送。

### D3-R14 · 底部状态栏与活动目标（P0）

**必须行为：**保留既有底部状态栏，展示与活动pane一致的环境、模式/输入所有者及已有必要状态。非活动pane通知采用轻标记，不让一个全局“Connected”覆盖所有目标；详细状态可点开。

**边界与实现：**实际布局变化才更新终端cols/rows；未知指标不能填虚拟延迟/TPS。状态栏是说明/导航，不授予写入权；切pane后等待数据时可写“正在核对”，不用前一个pane的状态。

**验收：**`D3-T14`。不会显示错主机/错误就绪；底部栏没有重复的全局大工具栏。

### D3-R15 · 命令菜单与快捷键可发现性（P1）

**必须行为：**现有菜单、Command Palette、tab右键与快捷键帮助统一动作名称和enabled条件。已有快捷键优先，新增频繁动作先列冲突表再分配；不通过新快捷键覆盖系统、readline或TUI。

**边界与实现：**macOS Cmd+C/Cmd+V与原始Ctrl+C必须区分；其他桌面按宿主注册值核对，不把所有Cmd机械替换Ctrl。用户定制键位优先，旧未知键位保留但不激活退役动作。

**验收：**`D3-T15`。标签、行为和帮助一致；无退役Toolbelt/Workspace入口复活。

### D3-R16 · 视觉回归与组件状态册（P1）

**必须行为：**在现有Flutter preview/golden入口增加受影响组件与真实数据fixture，按OS/字体/Flutter版本分开基线。保存同环境before/after与代表场景人工评审，不用大批金图通过代替关键原生截图。

**边界与实现：**自动快照只能证明给定fixture的渲染；原生应用证据仍必需。S1/S2已确定的安全行为不可为匹配样稿删掉；截图不是运行时背景图。

**验收：**`D3-T16`。差异有原因；所有新外观由真实控件实现；跨OS不伪造基线。

## 6. 阶段结果与退出条件

`results/D3.md` 按每个 `D3-Tnn` 建立三级标题，写操作、实际结果、测试日志、源码commit/path和原图嵌入。计划在 `plan.json`；实际结果填 `evidence/manifest.json`。

本阶段16项均满足证据下限，零开放P0/核心P1，聚焦测试通过、镜像无漂移，才可标 `verified`。设备/模型/原生App无法运行时标 `implemented_unverified` 或 `blocked`，继续交付可验证的代码与测试。后续代码影响旧场景时必须重新验证。
