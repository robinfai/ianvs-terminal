# 14 · 桌面键位、几何与滚动规范

> 2026-10-10 修订：与本文有关的敏感性、补充要求、收起/Esc、人工编辑保存和未知结果出口，统一以 [v1.1 交互修订](16_REVISION_1_1.md) 为准。原有 64 项需求及全部原生验收门槛保留。


所有尺寸是逻辑像素的设计起点，最终取值优先现有tokens并记录差异。16:9仅为标准示例画布，窗口仍可自由缩放。

## 1. 桌面几何

|部件|建议/保留规则|
|---|---|
|窗口顶栏|仅一层，建议38–44高，平台原生控制有安全空间；2×字体可自适应|
|底部状态栏|保留，建议24–28高，主环境/模式有详情；不可承载第二整排大工具|
|pane|终端内容+pane-local Composer，tab/pane活动标记不混同|
|Composer|环境、editor、动作三层；editor默认1行，增长至6行或min(240, pane内部高度×0.35)后内滚；不够显示最小安全信息则提供展开编辑|
|Block默认|整个块≤H/3；H为终端内容可用高度，不含Dock、状态栏、顶栏和其他外部工具|
|输出整数行|maxLines=floor(max(0,H/3−header−status−padding)/actualTerminalLineHeight)|
|极短pane|如metadata自身超H/3，摘要+Reader；不裁目标/退出码，不把字缩到难读；明确记录几何退化|
|手动展开|可突破默认H/3，按会话保留；保留回到默认入口|
|审阅层|建议宽720、上限min(1000,窗口可用宽−48)，高≤窗口可用高−48；正文可滚，动作可达；极短窗将目标/正文纳入可滚区，不覆盖唯一关闭入口|
|证据检查器|显式打开，主区≥600、检查器≥360，宽不足用同paneReader；默认无永久侧栏|
|间距/圆角|4/8/12/16/24栅格；Dock12、辅助组件6–8优先现有token，不重投影|

标准视口：960×600（小窗口）、1280×720、1440×810（设计册）、1920×1080；另有320宽split pane压力样本。不得按width<600直接套手机交互。菜单按window实际区域定位，不仅按屏幕大小。

输入中文/英文/emoji维持共同固定行高；实际Terminal cell度量必须来自当前字体/DPI。App主题切换不得改终端协议几何；真实resize由既有协调器处理。

## 2. 键位作用域表

这是一份行为合同，**不是授予随意新增默认快捷键的清单**。先导出现有action registry和用户键位。冲突条目使用现有有效键位，文档与UI同步更新；不机械地将macOS Cmd映射成Linux/Windows Ctrl。

|焦点/状态|键位|预期|
|---|---|---|
|IME composing|Enter/Tab/箭头|先由输入法处理；不提交、不采用应用候选|
|Command候选/历史有选中项|Enter或Tab|只采用；再次显式执行才可提交|
|Command普通ready草稿|Enter|同主按钮“执行”，满足lease等条件才有效|
|Command多行|Shift+Enter|换行；保留当前已有Ctrl/Option组合的兼容键位|
|AI草稿|Enter / Shift+Enter|发送 / 换行；明确去向，IME优先|
|展开草稿编辑|明确完成按钮|保存草稿不执行；文中Enter为编辑换行|
|Command可补全|Tab|按需查询/唯一候选采用；不给永久I/O许可|
|Command第一视觉行|↑ / 既有Ctrl+R|打开会话历史；非第一行↑移动光标|
|灰字预测|→、Ctrl+F/E及既有分段键|按现有语义采用，不隐式进入复制|
|应用文本编辑|macOS Cmd+Z / Cmd+Shift+Z|撤销/重做，不传PTY|
|应用复制/粘贴|macOS Cmd+C / Cmd+V|当前选择作用域；粘贴只进草稿，不执行|
|Composer清草稿|既有Ctrl+C|清当前本地草稿，不中断其他pane命令|
|Raw/TUI|Ctrl+C、Ctrl+R、Tab、Esc、光标键|由当前有效终端owner与应用光标模式处理，不被AI层偷走|
|Block导航|Composer已有Cmd+↑/↓；块内箭头/Shift范围|按当前配置进入块导航与范围选，不发送Shell历史键|
|Block搜索/过滤|已有Cmd+F、Alt+Shift+F等|作用当前选区/块/时间线，不跨pane|
|审阅层|Tab/Shift+Tab|在可访问控件间移动；初始聚焦目的/目标而非默认危险按钮|
|批准按钮真正获得焦点|Enter/Space|仅有效revision/target可激活；无全局Enter批准|
|最内层候选/menu/modal|Esc|关最内层；不冒泡去停止AI或发送给TUI|
|无弹层的任务视图|Esc|采用明确的返回/收起合同；不隐式中断命令|
|切窗口/系统输入源|Cmd+Tab、Ctrl+Space等系统键|不劫持，尊重OS及用户配置|

提供菜单/Command Palette可发现全部核心动作。重要动作必须同时有鼠标入口与键盘路径，不能仅有未提示的组合键。

## 3. 选择与复制优先级

先看实际primary focus：可编辑文本选区→输出文本选区→同pane选中的Block集合。其它pane保持视觉选区不表示成为复制目标。多块复制按显示顺序，原始硬换行保留、软换行按既有合同拼接；已淘汰输出明确不能恢复。

Ctrl+C是终端控制键，Cmd+C是macOS复制；Linux/Windows应尊重现有终端习惯和快捷键注册，不为了统一视觉把Ctrl+C复制覆盖掉。

## 4. 桌面双层滚动合同

指针命中可滚输出：先锁定当前手势到该输出；未到边界时外层不动。到边界后新的手势可以交外层，同一delta不能被父子重复消费。触摸板惯性中不突然跳到列表；鼠标无手势阶段时用明确边界策略并测试。

hover仅更新选中/说明，不滚动回高亮项。只有用户主动键盘导航、打开列表或改变查询才可自动定位候选。回看关闭tail-follow，新输出只给提醒；点“回到最新”才恢复。整页Reader可以单层滚动，不要求复制Block中的双层模型。

## 5. 原生焦点与首次点击

非key窗口收到鼠标点击先完成窗口/目标激活检查，不能把第一次点击直接转换成陈旧危险批准。回到窗口不自动执行草稿；打开modal后后台shell ready不得抢focus。FocusNode不能在build重建或共享给多个live视图；具体实现参考官方Flutter focus文档，并通过真实OS键盘验证。
