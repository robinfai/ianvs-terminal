# D4 PRD · 原生验收、性能与 GitHub 交付

> 2026-10-10 修订：与本文有关的敏感性、补充要求、收起/Esc、人工编辑保存和未知结果出口，统一以 [v1.1 交互修订](16_REVISION_1_1.md) 为准。原有 64 项需求及全部原生验收门槛保留。


**目标：**用真实桌面App、原生PTY/SSH、物理输入和可追溯构建证明D1–D3，不以自评替代证据。

**依赖：**冻结发布候选C，读取06、09、13；准备隔离fixture与真实设备/模型。

**非目标：**不发布App Store、不覆盖生产安装、不伪造缺少的平台/设备/模型结果。

## 1. 用户故事与交付判断

作为准备交付和审查产品的人，我要从GitHub独立复现关键场景，确定原图与代码相符、测试真正使用生产通路，并知道哪些平台/设备仍未验证。

本阶段每项需求均有独立case，表中步骤还须拆出其中包含的负向子场景。已有能力满足则补回归，不重复开发。所有“应/必须”为验收要求，不是本轮已完成声明。

## 2. 逐条需求

### D4-R01 · 真实本地 Shell 端到端（P0）

**必须行为：**用隔离开发构建、测试HOME/Profile与真实PTY执行本地zsh核心链路：失败块→诊断→审阅→批准→真实结果→总结引用。确定性模型fixture与真实API冒烟分开。

**边界与实现：**只能以实际App→生产controller→guard→nativePTY→Block通路计入端到端。harness直接调用controller、headless或Widget只作补证；保留真实命令和副作用的受控日志。

**验收：**`D4-T01`。零错目标/重复提交；视频、原图、原生回执一致。

### D4-R02 · SSH、Bash/Zsh与多跳（P0）

**必须行为：**在受控SSH主机验证已协商Bash4+/Zsh、现有双跳和不支持shell的保守降级。每节点租约与上下文必须独立，模式变化准确表达；不把远端补全/历史当已支持。

**边界与实现：**本地Bash/fish安全提交只有最新实现真的支持才能宣称；无适配器使用仅编辑/Raw。测试主机独立，禁止用用户生产服务器执行故障fixture。

**验收：**`D4-T02`。任务绑定正确节点；不可用时不盲打Enter；恢复需重新核对。

### D4-R03 · 真实模型 API 与错误注入（P0）

**必须行为：**至少一个真实模型API完成桌面诊断及一次受控批准；记录返回模型标识/计费信息可用性，不能只记配置名冒充实测。另用mock覆盖认证/网络/格式/超时。

**边界与实现：**不承诺模型必做对；业务任务成功须fixture verifier确认，模型失败与产品失败分别记录。敏感prompt与凭据不入仓；不同提供方支持边界不得被UI隐藏。

**验收：**`D4-T03`。真实路径可复核；故障不隐式重试命令；分类清晰。

### D4-R04 · 本地 ACP 的原生闭环（P0）

**必须行为：**真实本地适配器验证检测、测试、保存、执行、取消、session/load恢复及配置替换；Finder最小PATH单列。对生产终端只开放现有受控工具与宿主审阅。

**边界与实现：**不以登录文件存在当认证成功；不在PRD里硬编码过时模型可用性。测试记录实际适配器/模型/effort，缺失环境明确blocked；不可转成API后声称ACP通过。

**验收：**`D4-T04`。恢复无重放、权限无扩大、返回模型可核对；配置替换不接续旧授权。

### D4-R05 · Manual 与 Smart 审阅回归（P0）

**必须行为：**两种审阅模式分别验证：手工均需用户确认；Smart按现有强制规则与独立模型审阅控制低风险自动通过。UI显示审阅中、通过/需确认、原因与对应操作，不能显示绝对安全。

**边界与实现：**切换Smart不是整个Session永久授权。编辑命令/目标变化需重审，模型审阅失败保守要求确认；审阅自身不持终端写工具。高危示例只用于拦截测试，不执行真实破坏性命令。

**验收：**`D4-T05`。无规则绕过；原因可见；Smart未知结果不能变自动批准。

### D4-R06 · 重复、陈旧与竞争故障矩阵（P0）

**必须行为：**固定覆盖双击批准、旧revision、目标切换、迟到AI/补全、同id变参数、partial send_keys、未知receipt、接管竞争、关闭pane后回调。需要生产路径检查、负向测试与受控副作用验证三层。

**边界与实现：**有效operation次数≤1不是write次数≤1；同id重查回既有结果。未知与拒绝区分，不能为了跑通清理pending。测试不改变生产gate默认策略。

**验收：**`D4-T06`。零未授权有效提交；错target/旧revision被拒绝；partial progress诚实可恢复。

### D4-R07 · 真实键盘、输入法和触摸板（P0）

**必须行为：**使用实际Mac键盘与物理触摸板完成Enter/Tab/快捷键作用域、拼音composition、长文选择、惯性滚动与菜单操作；外接非美式布局可作为补充，不假设所有modifier都可用。

**边界与实现：**自动注入若未发送正确modifier，归为采集工具失败，不能当产品键位失败或通过。保留实际设备、输入法、键盘布局和观察者记录；无设备则implemented_unverified。

**验收：**`D4-T07`。物理输入与自动断言一致；不抢焦点、不双层跳滚、不意外执行。

### D4-R08 · 多会话、分屏与长任务（P0）

**必须行为：**至少四个pane、两个tab并发：A长命令、B AI待审批、C编辑、D TUI/只读；切tab、移动pane、关闭取消、后台回复都保留来源与输入隔离。

**边界与实现：**不引入多Agent并发同一PTY。已有任务在非活动pane可继续合法执行，但通知不能抢焦点；布局恢复新建PTY不恢复死进程。

**验收：**`D4-T08`。无错写、错状态、草稿丢失或任务串联；通知指向原pane。

### D4-R09 · 真实 TUI、密码与特殊输出（P0）

**必须行为：**实际vim/top或已安装等价程序验证全屏、鼠标报告、光标/键位与退出。一次性密码输入场景确认不上传秘密、不进入Composer草稿/模型上下文；特殊图像/未归属输出保守回退。

**边界与实现：**AI键序列使用现有显式控制键和取消检查。只读observer无UI写入但核心协议应答仍正常；截图必须用fixture且不拍密码。

**验收：**`D4-T09`。无错键、泄密或半截画面；只读控制明确；恢复Blocks由用户触发。

### D4-R10 · 断连、休眠与恢复（P0）

**必须行为：**分别测试AI网络、SSH链路、进程结束、电脑sleep/wake；在待审、提交未知、运行中各断开。恢复先核对目标/回执/所有权，不暗示已自动重新执行或恢复死进程。

**边界与实现：**App关闭/崩溃后内存任务不保证恢复；Layout relaunch是新Session。网络变化不构成重新授权。测试限定隔离连接，不切断用户实际业务。

**验收：**`D4-T10`。未知不被误判未执行；不重放；新PTY不伪装旧运行；用户可以看清限制。

### D4-R11 · 原生无障碍验收（P1）

**必须行为：**在真实macOS开启Full Keyboard Access与VoiceOver，完成从失败块到证据回看；记录名称/角色/状态/焦点顺序。关闭modal回触发点；后台日志不逐行播报。

**边界与实现：**自动Semantics测试不能代替真实读屏。可能影响VoiceOver的Ctrl+Option组合必须与默认系统键位一起测试；不为自定义快捷键关闭系统辅助功能。

**验收：**`D4-T11`。核心流程无需鼠标；审批目标清楚；无陷入循环/无读序。

### D4-R12 · 原生 DPI、字体与多显示器（P1）

**必须行为：**真实桌面显示器验证标准与HiDPI/缩放，移动窗口时重测cell、浮层与选择；Mac不同系统/架构覆盖按实际设备记录。基线支持范围不等于实测完成。

**边界与实现：**没有第二台显示器不能用修改截图像素假装通过；Widget DPI模拟只补覆盖。桌面1/1.5/2文字缩放与原生字体等宽必须区分于系统DPI。

**验收：**`D4-T12`。不模糊错位、丢字、overlay漂移；关键动作可达。

### D4-R13 · 性能、内存与长输出（P1）

**必须行为：**profile构建测试真实App，release补冒烟。128保留块、四pane、受控持续输出与Reader分页、20次开关任务/审阅/读取的循环形成基线。对比相同OS/设备/构建模式/fixture。

**边界与实现：**建议门槛：可见本地反馈p95≤100ms；UI/raster分别p95≤实测刷新预算，超预算帧≤2%；稳定态内存相对预热基线增量≤max(15%,30MiB)且无单调泄漏。基线已差须报告失败/原因，不偷偷改阈值。模型延迟不混入UI指标。

**验收：**`D4-T13`。无崩溃/OOM/无界缓冲；未达阈值明确failed；数据可复算而非目测“流畅”。

### D4-R14 · 构建、数据与回滚（P0）

**必须行为：**运行现有format/analyze/tests/镜像检查/真实Composer gate/make verify。构建签名开发App并在隔离目录运行；Profile、SSH凭据、Recording、Layout与optional sync保持原有数据合同。

**边界与实现：**不默认make install覆盖/Applications中的生产版；不更改bundle身份或签名凭据以绕过验收。回滚只恢复合法配置与新Session，不承诺复活PTY。无关后端/同步改动不夹带。

**验收：**`D4-T14`。无数据丢失/伪恢复；签名与运行产物可对照；完整gate原始结果保留。

### D4-R15 · Linux／Windows 桌面验证边界（P1）

**必须行为：**先审最新分支实际host、native依赖、构建/包、PTY、SSH、IME与ACP能力，再分平台记录supported、implemented_unverified或not_supported。Mac通过不能称三桌面通过。

**边界与实现：**此需求的基础交付是诚实平台矩阵与源码证据，不强制在本轮从零移植缺失host。若最新branch已经承诺并提供Linux/Windows宿主，则追加各平台原生App+PTY核心路径、字体/键位/DPI/包装验收；缺环境保持该平台未验证。

**验收：**`D4-T15`。可以单独判macOS桌面完成；Linux/Windows不得被UI-only/build-only结果标已验证；平台claim有独立证据。

### D4-R16 · 最终 GitHub 可审查交付（P0）

**必须行为：**实现、文档、测试、原图/必要录屏/日志与manifest一同可从GitHub获取；每需求有case和代码落点，每case有行为证据及截图检查点，结果文档直接嵌图。提交FINAL_REVIEW与实际环境矩阵。

**边界与实现：**冻结实现C采证，证据E单独提交；最终重新验证所有受最终修改影响场景。跨旧commit复用必须依赖闭包/源hash未变且有人审，不能只说“应该不影响”；自动校验器不认此类复用为自动通过，人工批准另记。

**验收：**`D4-T16`。零开放P0/核心P1；未验证项如实列出；不能用全绿表格代替实际附件。

## 6. 阶段结果与退出条件

`results/D4.md` 按每个 `D4-Tnn` 建立三级标题，写操作、实际结果、测试日志、源码commit/path和原图嵌入。计划在 `plan.json`；实际结果填 `evidence/manifest.json`。

本阶段16项均满足证据下限，零开放P0/核心P1，聚焦测试通过、镜像无漂移，才可标 `verified`。设备/模型/原生App无法运行时标 `implemented_unverified` 或 `blocked`，继续交付可验证的代码与测试。后续代码影响旧场景时必须重新验证。
