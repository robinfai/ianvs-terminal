# 移动端会话与断开记录

移动端的连接首页和会话选择器使用同一套状态和操作。

| 内容 | 展示与操作 |
| --- | --- |
| 进行中的会话 | 显示名称、主机和运行状态；点击进入终端；“断开连接”结束该会话。运行状态表示本地 SSH 会话仍在运行，不承诺远端认证已经完成。 |
| 已断开的记录 | 默认折叠；显示主机、退出码；点击“查看输出”进入只读终端。可以重新连接或移除记录。 |
| 已重新连接的旧记录 | 显示“已重新连接 · 历史输出”；“进入当前连接”打开已有的后继连接，不再新建。 |

- 返回连接首页仅导航，不断开 SSH。
- SSH 退出码 255 的输出保留用于诊断；普通退出遵循原有关闭策略。
- 断开详情持续显示说明与重连入口；键盘和新录制入口不可用，输出搜索、复制及已有录制保存仍可使用。
- 横屏或键盘尚未收起导致空间不足时，提示改为紧凑布局并优先保留重连按钮；完整说明仍可通过长按提示和辅助功能读取。
- 重连创建新的底层会话身份，不重放命令；重复请求合并。再次失败时，从任何较早记录发起重连都会继续最新尝试，并保留其命令草稿和已有 AI 对话。
- 同一主机上用户主动新建的独立会话仍相互独立，不因主机相同被合并。
- 选择器随会话变化更新。逐项移除保持面板打开；“清理已断开”仅清理断开的记录，不影响运行中的连接。
- 被其他会话的 AI 对话引用的记录暂不可移除，界面说明原因。结束该对话所属的当前会话后可移除；批量清理先处理较新的已断开会话，再处理释放引用的旧记录。录制与传输的既有关闭保护仍生效。
- 记录保存在当前 App 进程中，移除记录或退出 App 会清除其临时输出；需要跨启动保存的内容使用录制功能。

## 启动恢复

开启恢复布局时，新保存的布局只包含未退出的会话。过滤断开 pane 后会折叠空分屏、移除空 tab，并调整活动位置。当前进程里的历史输出和 AI 引用不会因此被清理。

旧版 v1 布局文件没有保存退出状态，升级后的首次读取无法判断某一项过去是否已经断开；保留原有解析规则，避免误删用户有意创建的并行会话。新保存的布局开始执行上述过滤。

## 回归覆盖

- `mobile_session_list_test.dart`：分组、状态、动作、响应更新、窄屏与深浅主题。
- `mobile_disconnected_session_notice_test.dart`：中英文断开说明、深浅主题、紧凑提示、完整语义说明与至少 44pt 的可点击区域。
- `mobile_sessions_lifecycle_test.dart`：实际 Shell 的返回、断开、重连、选择器更新和清理流程。
- `shell_ai_reconnect_test.dart`：AI 引用、未确认回执、草稿、多次重连和无 AI 的普通会话。
- `session_state_test.dart` / `session_controller_test.dart`：重连去重、后继链、删除中间节点与独立会话。
- `local_session_layout_codec_test.dart`：过滤断开 pane、布局修剪、活动位置及旧格式兼容。
