# T-328 Replay Checkpoint Seek

## Goal

Add deterministic replay seek by restoring a real materialized checkpoint and
fast-forwarding the recorded stream to an exact monotonic offset, while
preserving compatibility, Runtime Event ordering and realtime scheduling.

## Scope

- Add public ReplayBackend seek capability, duration and per-session offset.
- Require both current recording schema checkpoint markers and native checkpoint support.
- Select the latest materialized checkpoint at or before the target.
- Restore native terminal state, then synchronously replay events through the
  target offset with inclusive same-timestamp semantics.
- Resume realtime scheduling from the requested offset and configured speed.
- Keep no-delay replay positioned at the requested offset after seek.
- Preserve events pending before seek and discard only lifecycle events
  regenerated by seek fast-forward.
- Return the selected checkpoint and bounded replay/discard counts.
- Surface failed native restore as `TerminalReplaySeekException`.

## Non-goals

- Do not add pause, scrubber UI, recording-library UI or product wiring.
- Do not seek recordings or delegates without checkpoint support.
- Do not serialize native snapshots or guarantee restore after native eviction.
- Do not replay historical user input or enable Host side effects.
- Do not add graphic asset bundles or cross-process instant seek.
- Do not reset or reuse Runtime Event sequence numbers.

## Seek Contract

- The target is an inclusive monotonic offset in `[0, replayDuration]`.
- A checkpoint is eligible only after it has materialized in the current native
  replay session. Forward seek can materialize later markers while fast-forwarding.
- When multiple checkpoints share the target offset, the checkpoint with the
  greatest resume event index is selected because it represents the most complete
  state at that inclusive timestamp.
- Restore happens before the active realtime timer is cancelled. A failed restore
  leaves the prior timeline and timer active.
- Fast-forward delivers output, resize and exit events whose offsets are at or
  before the target; checkpoint markers already materialized are not captured again.
- Realtime schedules the next event from the requested offset using the existing
  absolute speed-scaled timeline. No-delay mode creates no new timer.
- Pending pre-seek Runtime Events are buffered and returned once. Events generated
  only by fast-forward, such as a repeated exit, are drained internally so product
  lifecycle does not run twice. Native Event sequence remains monotonic.
- If native capacity has evicted an opaque checkpoint id, restore fails explicitly;
  the Dart layer does not pretend it can reconstruct an unavailable snapshot.

## Functional Acceptance

- Backward seek restores the initial checkpoint and replays only events through
  the requested intermediate offset.
- Exact seek chooses the latest checkpoint at a shared timestamp without replay.
- Realtime seek cancels the old timer only after restore and schedules from target.
- V1/legacy delegates, negative targets and targets beyond duration fail explicitly.
- Failed native restore keeps the original timer and reported offset.
- Pre-seek events remain observable once and regenerated exit is discarded.
- A real native-core bridge restores a Frame that excludes post-target output.

## Result

T-328 is closed. The 20 focused ReplayBackend regressions pass, including the
real native-core Frame restoration proof. The complete repository gate passes
1,733 vendor Rust tests with one ignored case, 131 native-core unit tests, 518
native session tests, 3 `vttest` regressions, 57 PTY tests, 543 terminal tests
with one intentional skip, 12 documentation contracts, 1,100 example tests, 4
macOS smoke tests, 46 real PTY tests and all 17 XCTest cases. All six benchmark
rows report `hash_match=true` in
`build/bench-results-ci/20260721T115621Z`.

The verification run also removed two unrelated timing races exposed by the
full-load gate: idle-wake children now remain alive until their strict
250/750ms refresh assertions complete, and the profiles smoke flow waits a
bounded interval for its asynchronous sheet and tab. Neither change relaxes a
product-performance threshold or changes Replay behavior.

## Risks / Follow-ups

- Native byte-budget eviction is intentionally visible as a failed restore. A future
  product controller may rematerialize from an earlier surviving checkpoint.
- Seek reconstructs terminal/parser state, but portable graphic asset persistence
  remains the separate Graphics Assets work package.
- Pause and scrubber interaction need their own lifecycle contract before UI wiring.
