# `example` UI 精致紧凑化设计

## 背景

这一轮不重做信息架构，也不再扩展组件范围。目标只有一个：把当前 `example` 里的桌面界面从偏厚、偏松、偏软，收成更像专业工具的细密状态。

现状问题集中在三类：

- 外壳太厚：工具栏、标签栏、对话框头部、底部操作区都偏高。
- 控件太鼓：按钮、输入框、图标按钮点击框偏大，圆角偏软。
- 空白太重：面板套面板时，内外边距叠加，页面显得发胀。

这份设计基于已经落下去的基础层：

- `example/lib/ui/foundation/*`
- `example/lib/ui/components/*`
- 已迁移页面壳：`ShellScreen`、`DefaultsAndAppearanceDialog`、`ProfileEditorDialog`

## 目标

- 保留桌面工具的可读性和可点性，但显著提升信息密度。
- 优先收紧工具栏、标签栏、对话框头部、按钮、输入框、面板留白。
- 正文只缩小半档，标题层级基本不动，避免全局一起发干。
- 圆角明显收小，边框更利落，但不靠加粗边框制造“硬朗感”。

## 非目标

- 不改 `packages/flutterm_terminal` 的公开接口。
- 不新增 UI 依赖。
- 不把当前界面改成移动端优先。
- 不在这一轮继续扩大组件库范围。

## 设计方向

整体方向选择“操作台高密”，但不做极端压缩。原则是：

- 该高密的地方高密：工具栏、标签栏、对话框头部、表单单行字段、按钮行。
- 该留气口的地方留气口：section 开头、空状态、终端内容区外围。
- 不靠大字号差和大空白差做层级，改靠字重、颜色、局部留白和状态清晰度。

## 全局基线

### 间距基线

把当前偏厚的节奏改成更短的一组：

- `xs = 3`
- `sm = 6`
- `md = 10`
- `lg = 12`
- `xl = 16`
- `xxl = 20`

使用规则：

- 同组字段、按钮、短说明之间：`6-8`
- 小节之间：`10-12`
- 大区块之间：`14-16`
- 页面或对话框外圈主要留白：尽量不超过 `16-20`

### 圆角基线

圆角明显收小：

- `sm = 6`
- `md = 8`
- `lg = 10`
- `xl = 12`

原则：

- 按钮、输入框、标签、面板默认只用到 `sm/md/lg`
- `xl` 只保留给对话框外壳和少量大面板
- 不再出现鼓胀的大圆角按钮和厚面板

### 字体基线

- 正文主字缩小半档，目标感受接近 `13`
- 辅助文字和说明文字缩到 `11.5-12`
- 标题字号基本不动
- 标题通过更紧的行高和更稳的字重来提炼，不通过继续放大来做层级

字体层级建议：

- `titleLarge` 保持当前档位，但行高收紧
- `titleMedium` 用于 section 标题，字重明确，间距缩短
- `bodyMedium` 下压半档，作为主要正文和字段内容
- `bodySmall` 与提示文案统一偏细，不再松散漂浮

### 控件尺寸基线

- 常规按钮高度：`34-36`
- 紧凑按钮高度：`28-30`
- 单行输入框高度：`32-34`
- 图标按钮点击框：`28-30`
- 工具栏图标尺寸保持克制，不因控件变薄而放大图标

### 边框与层次

- 边框线宽保持 `1`
- 焦点态和选中态仍靠颜色和对比度拉开
- 不通过加粗边框去弥补层级

## 基础层修改规则

### `AppThemeTokens`

需要调整的 token：

- `spacing`
- `radius`
- `elevation` 的模糊半径和位移也应略收，避免悬浮感太重

阴影方向：

- 浮层和对话框阴影都要更短、更贴边
- 目标不是“飘”，而是“压住层级”

### `buildFluttermTheme`

需要同步收紧：

- `filledButtonTheme`
- `outlinedButtonTheme`
- `textButtonTheme`
- `iconButtonTheme`
- `inputDecorationTheme`
- `textTheme`

其中重点：

- 按钮 padding 下压一档
- 输入框 vertical padding 下压一档
- 图标按钮默认视觉密度转向更紧凑
- 文本主题中 `bodyMedium/bodySmall/titleMedium` 的字级和行高要重新对齐

## 基础组件修改规则

### `AppToolbar`

- 默认高度改到 `40-42`
- 左右 padding 改到 `10-12`
- 标题和副标题之间只保留极短缝隙
- 动作区按钮默认用紧凑尺寸

### `AppPanel`

- 默认圆角使用更小档位
- 默认内边距不再偏厚，除非调用方明确要求
- 阴影只用于必要浮层；普通面板更像“贴着界面”的结构壳

### `AppDialogScaffold`

头部、正文、底部都要一起变薄：

- header 上下边距：`14-16`
- 标题与副标题间距：`3-4`
- body 四周边距：`12-16`
- footer 上下边距：`10-12`
- 关闭按钮点击框改用更紧凑的图标按钮尺度

### `AppActionButton`

- `regular` 进入 `34-36` 高区间
- `compact` 进入 `28-30` 高区间
- 图标和文字之间的距离缩短
- danger/primary 只靠颜色和字重区分，不靠更大的 padding

### `AppFieldRow`

- label 与 control 间距缩短
- hint/message 进入更小一档文字
- 多行说明避免占掉一整块空白

### `AppSectionHeader`

- section 标题上下留白收短
- 不再像一个独立 banner
- 如果存在说明文案，说明文案紧贴标题，不单独撑大一个区块

### `AppEmptyState`

- 标题和说明之间距离缩短
- 说明文字不拉太宽
- 行动按钮贴近内容主体，不再像页尾 call-to-action

## 页面壳落地规则

### `ShellScreen`

收紧重点：

- 顶部 chrome
- 标签栏
- workspace cue

具体规则：

- 顶部壳体要明显变薄
- tab 高度和 tab 内左右 padding 一起下压
- 快捷键文字小半档
- 选中态靠底色、字重、边框清晰度，不靠更高更大
- 终端内容区外围留白保留克制呼吸感，不压迫终端内容

### `DefaultsAndAppearanceDialog`

收紧重点：

- 对话框头部
- 主题切换与默认 profile 选择区
- footer 按钮行

具体规则：

- 头部更薄，但标题保持明确
- 选项组之间不要再靠厚 padding 隔开
- footer 高度降低，按钮改紧凑
- 中间选项区仍保留少量节奏，避免变成纯参数表

### `ProfileEditorDialog`

收紧重点：

- section 间距
- 单行字段密度
- 颜色编辑和操作区

具体规则：

- 字段行进入高密布局
- section 与 section 之间保留少量停顿，不做表格式压扁
- 颜色预览、重置按钮、辅助提示都要薄
- 底部主操作按钮区收短，但保留清晰主次

## 密度分区

### 必须高密

- 工具栏
- 标签栏
- 对话框头部
- 表单单行字段
- 按钮行
- 面板过渡区域

### 必须保留一点呼吸感

- section 起始处
- 空状态
- 对话框正文里的大区块开头
- 终端区外围壳与终端内容之间

### 必须避免的写法

- 大圆角按钮
- 厚弹窗头
- 多层面板每层都带一圈大 padding
- 用“大标题 + 大副标题 + 大空白”来堆层级

## 验收标准

实现后，界面需要满足这些视觉结果：

- 第一眼不再显得厚、鼓、松
- 工具栏、标签栏、对话框头部明显更薄
- 按钮和输入框更像桌面工具，而不是展示型卡片界面
- 正文仍然可读，不出现“全部变小所以更难看”的反效果
- section 仍有节奏，不会因为压密而糊成一片

## 实施顺序

1. 先改 token 和主题基线
2. 再改基础壳组件
3. 最后对 `ShellScreen`、`DefaultsAndAppearanceDialog`、`ProfileEditorDialog` 做定点收边

这样做可以保证变化先从全局基线一致，再去磨最显眼的地方，避免每个页面各自手调。
