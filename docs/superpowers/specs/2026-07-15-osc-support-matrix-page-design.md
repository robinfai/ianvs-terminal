# OSC 支持矩阵页面设计

## 目标

在 GitHub Pages 站点新增独立的 `/osc/` 页面，向用户说明 Ianvs 当前支持的 OSC 序号、协议来源、支持状态、核心能力和主要场景。页面内容以主分支的 `docs/protocols/osc_support_matrix.md`、当前 OSC 分发代码和共享协议语料为依据。

## 页面结构

1. 页面头部沿用现有站点导航、品牌和主题切换。
2. 简短说明 OSC 只定义控制序列外壳，大多数序号语义来自 xterm、Kitty、iTerm2 等实现；页面把来源分为事实标准、三方规范、社区规范和 Ianvs 私有。
3. 用摘要卡片说明当前覆盖范围、受权限控制的能力和明确不支持的边界。
4. 按来源拆成四组静态矩阵：
   - xterm 与通用事实标准；
   - Kitty；
   - iTerm2；
   - VS Code、ConEmu/Windows Terminal、urxvt、UAPI 与 Ianvs 私有协议。
5. 每组表格固定使用“OSC、来源、状态、核心能力、主要场景”五列。
6. 页面底部链接到 GitHub 主分支的完整证据矩阵，并注明页面对应的仓库口径日期。
7. 在现有技术页的“Repository evidence”区域新增 OSC 支持矩阵入口，不修改全站主导航。

## 交互与响应式

页面不增加搜索、筛选或新的 JavaScript 状态。桌面端直接展示完整表格；窄屏下只允许表格容器横向滚动，页面本身不能横向溢出。表格使用原生 `table`、`caption`、`thead`、`tbody` 和带 `scope` 的表头；已有跳转正文、主题切换和焦点样式继续复用。

状态不能只靠颜色表达。若增加状态标签，标签文字必须完整表达“支持”“安全子集”“权限控制”“不支持”等含义，深浅主题均使用现有 CSS 变量。

## 内容边界

- 纳入当前产品矩阵中的 OSC 项；不纳入同一文档里的 CSI 标题窗口操作。
- OSC 1337 按会话元数据、变量与 Unicode、外观、终端内交互、图像/文件/外部动作分组，避免一行塞入全部子命令。
- 明确写出 OSC 23 是安全空操作、OSC 72 仅支持 macOS 接收端、OSC 52 仅处理文本、OSC 99 不执行通知命令、OSC 1337 RequestUpload/StealFocus/SetProfile 不授权。
- 不把解析器分支等同于完整产品支持，也不把尚未执行的参考终端对比写成已验证。

## 修改范围

- 新增 `osc/index.html`。
- 更新 `technology/index.html`，增加页面入口。
- 更新 `assets/styles.css`，只增加矩阵页需要的摘要、状态标签和表格滚动样式。
- 更新 `tools/validate_site.py`，把新页面和链接纳入静态校验。
- 更新 `README.md` 的页面清单和本地预览说明。

## 验证

1. 运行 `python3 tools/validate_site.py`，检查六个页面、公共资源和内部链接。
2. 检查 HTML 语义、唯一标题层级、表头作用域、跳转正文和主题控件。
3. 检查 320px、平板和桌面宽度，确保只有表格容器可横向滚动。
4. 检查浅色、深色和系统主题下的正文、边框、状态标签对比。
5. 对照主分支矩阵逐项核对 OSC 序号、来源、状态和限制，并运行共享 OSC 语料校验。

## 非目标

- 不增加客户端筛选、搜索、排序或虚拟列表。
- 不重构现有站点导航和视觉系统。
- 不修改 OSC 实现、测试语料或主分支协议文档。
- 本次不发布到远端；先在本地 `gh-pages` 完成并验证提交。
