# xterm.js Recent Fix Audit

Audit window: 2025-05-13 through 2026-05-13, inclusive.

Purpose: use xterm.js as the comparison benchmark for ianvs terminal terminal behavior. This is not a migration plan. Product code must not be changed from this audit alone; rows marked `Gap`, `Needs probe`, or `Manual queued` need a focused task card, regression probe, or human-confirmation record before implementation.

## Source Layers

- Stable release notes: [xterm.js 6.0.0](https://github.com/xtermjs/xterm.js/releases/tag/6.0.0), published for `@xterm/xterm` on 2025-12-22.
- Beta/current line: `@xterm/xterm` `6.1.0-beta.*` npm history through `6.1.0-beta.219`, published on 2026-05-12, plus `xtermjs/xterm.js` git history after tag `6.0.0`.
- ianvs terminal baseline: [ARCHITECTURE.md](ARCHITECTURE.md), [TERMINAL_XTERM_API_ALIGNMENT.md](TERMINAL_XTERM_API_ALIGNMENT.md), [KNOWN_ISSUES.md](KNOWN_ISSUES.md), [TESTING.md](TESTING.md), and current terminal/runtime tests.

## Status Vocabulary

Every matrix row uses exactly one current status:

- `Covered`: direct implementation and regression evidence exists.
- `Likely covered`: architecture or code path strongly suggests parity, but the exact xterm.js symptom is not locked by a named regression yet.
- `Needs probe`: plausible risk remains and the next action is a focused automated or manual check.
- `Gap`: ianvs terminal is missing the behavior or has a known conflict.
- `Manual queued`: automated/source evidence is recorded, but final confirmation needs platform, visual, performance, or product-scope review tracked in [XTERM_MANUAL_CONFIRMATION_QUEUE.md](XTERM_MANUAL_CONFIRMATION_QUEUE.md).
- `Not applicable`: the fix targets xterm.js browser, DOM, WebGL, or addon internals with no ianvs terminal equivalent.
- `Deferred`: relevant only after a future feature or addon boundary exists.

## ianvs terminal Baseline Map

- Input, keyboard, paste, and shortcut routing live in `TerminalInputController` and example input tests.
- Flutter terminal rendering, scrolling, IME attachment, hit testing, links, and selection live in `TerminalViewport`, `TerminalViewportState`, and selection/render tests.
- VT parsing, alternate screen state, modes, OSC handling, hyperlinks, frame diffs, and resize behavior are owned by `native/core`.
- xterm-like facade APIs live in `packages/ianvs_terminal/lib/src/xterm/terminal_api.dart`.
- The current architecture intentionally does not expose xterm.js DOM/WebGL renderers, browser decorations, JavaScript parser hooks, or the first-party xterm addon ecosystem.
