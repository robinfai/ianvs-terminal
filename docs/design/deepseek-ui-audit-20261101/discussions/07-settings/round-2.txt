**定案方案（最终方案）**

1. **P1 表单字段统一（iOS `同步` / macOS `数据同步`）**
   - **布局**：桌面端保留左侧标签右对齐、控件对齐基线；手机端改为顶部标签 + 全宽输入框（当前 iOS 的浮动标签一并回退为常规顶部标签）。
   - **输入边界**：统一 1pt 描边、圆角 6pt（macOS）/ 8pt（iOS）；输入框高度建议 iOS 44pt、macOS 28pt。
   - **收益/风险**：消除两端描边与浮动标签差异，降低表单拼装感；风险是需回归旧版输入校验逻辑。

2. **P1 保存按钮状态与状态栏位置**（macOS `常规`/`外观`/`同步`）
   - **状态逻辑**：保存按钮启用条件 = `hasChanges && valid && !isInProgress`（当前截图“未填写即禁用”符合此条件，保留）。主按钮仅在满足该条件时用品牌蓝实底，否则保持描边灰。
   - **底部栏**：保持固定在底部，不随内容滚动出现遮挡。
   - **收益/风险**：维护现有“表单不完整即禁用”的保护，仅补上 valid 校验；风险是需确保 valid 更新为异步时无闪烁。

3. **P1 模式说明表重构**（macOS `数据同步`）
   - **调整**：将三行四列表格缩为三个简短的单列可选项：“本地终端”“内置本地服务”“远程 API 服务”；选项下方保留单行说明（如“通过你的服务同步”）。
   - **状态标注**：当前模式（本地终端）保留但标记为“已应用”；若用户轻点其他模式，未保存前在选中项旁标注“待保存”。
   - **收益/风险**：保留“当前本地模式”的真实含义，同时降低表格视觉权重；风险是需确认“待保存”状态不会与脏状态栏冲突。

4. **P2 说明文字与重复标题精简**
   - **常规页**：删除“新会话→默认连接”“语言→界面语言”中重复的大标题；说明文字最多 2 行（例如 iOS 优先终端模式说明），超出部分改为“了解更多”展开。
   - **例外**：关键失败、风险及错误提示（如登录接口报错）必须完整展示，不折叠。
   - **颜色**：说明文字统一使用 `secondary` token，实测对比度达到 4.5:1 以上，拒绝不透明的硬编码 60% 灰色。

5. **P2 外观组与 iOS 选项**
   - **外观卡片**：维持原生对勾逻辑，不改为 Radio，只将卡片内分隔线左右内缩 16pt，行高保持 44pt 以增强可点感。
   - **收益/风险**：符合 iOS 平台习惯，视觉上更容易辨认区块。

**明确不改什么**
- 不改保存按钮语义（不允许仅凭 hasChanges 启用或染蓝）。
- 不改当前已应用的本地终端状态，不直接删掉。
- 不将 iOS 对勾选项换成 Radio 按钮。
- 不擅自固定底部输入栏的留白为缺陷。
- 不基于未捕获 Apple 原生登录及已登录卡截图做任何断言或推断。

**验收条件**
1. 保存按钮必须满足 `hasChanges && valid && !isInProgress` 时才可呈现主操作实底，否则应处于禁用描边状态；且底部栏在所有页面内容滚动时位置稳定。
2. 表单所有输入框需具备明确边界与顶部标签，说明文字统一使用 `secondary` token 且对比度 ≥ 4.5:1；常规说明超过 2 行时，“了解更多”可触发展开，失败/风险提示不折叠。

**局限**
- 以上尺寸参数（如输入框高度、分隔线内缩 16pt）均为待落地验证的建议值，非截图测量；两端的动态字体适配、禁用按钮视觉密度未在截图中体现，需后续补测。
- 未捕获 Apple 原生登录界面及已登录卡片，无法对授权流程和登录态展示得出最终结论。
