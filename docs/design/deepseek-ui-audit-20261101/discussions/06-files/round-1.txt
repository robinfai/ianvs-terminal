同意你的前提：macOS 全宽仅作夹具；无可靠元数据则不增列。以下为第一轮审查。

**1. 整体判断**
结构干净、双端方向正确：iOS 用标题+副标题交代目标，macOS 用行头图标+标题区分面板。层级主要靠“工具栏路径/刷新”和“行尾操作”承载，目前最大的问题是路径区语义与视觉都偏弱、双端行尾操作符号不统一。P2

**2. 问题清单**

P1｜iOS 浅/深 SFTP｜工具栏中的 “/” 路径 → 为只读裸文本，缺少地址/面包屑容器感，与上行 home、up 图标视觉权重不匹配；当前根路径用户不易辨识。建议：路径文本改用 secondary label 色（与图标同灰阶），并置于至少 44pt 高、可横向裁切的胶囊/描边容器中；显示 “根目录 /” 或 “/（根目录）” 轻标签。收益：明确“当前位置”；风险：若面包屑扩展会增加点击热区，需确认是否可点。P1

P1｜iOS 双主题｜行尾 “…” → 与 macOS 的 “>”（目录）和省略操作表达不一致；在本场景无大小/时间时，“…” 更接近“更多操作”，但目录行缺乏进入暗示。建议：目录行行尾统一用 chevron.right（14pt，secondary）；文件行用 ellipsis（SF 等价），二者同宽占位。收益：双端一致、层级更清晰；风险：若真机交互是长按/滑动操作，需与我确认。P1

P2｜macOS 双主题｜行高与留白 → 三行之间约 60pt 行距，相对 1280 宽显得稀；列表像被拉散。建议：行高 52–56pt、图标与文本基线对齐，整行 hover 底色；标题与工具栏间距略收。收益：增强列表聚合度；风险：若实际面板更窄，收紧后需复测。P2

P2｜iOS 浅/深｜标题区 → 副标题连接串 “deploy@prod.example.com:22” 虽清楚，但与标题几乎同级粗细，主题切换后对比变化不明显。建议：副标题降至 caption1，secondary；标题保持 headline。收益：主次更清晰。P2

P2｜全图｜图标几何 → 蓝色文件夹/文件图标轮廓偏细，在深色背景上边缘略弱；macOS 文件图标与 iOS 视觉尺寸接近，但行内缩进与标题不对齐更醒目。建议：图标统一 20pt 命中框，与文本左缘间距 12pt；线宽与正文一致。收益：扫视更整齐。P2
