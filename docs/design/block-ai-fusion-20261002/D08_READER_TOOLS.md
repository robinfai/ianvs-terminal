# D08 / M04 阅读页工具与输入交接

2026-10-03，`composer` 工作区，macOS 27.0.1（26A434）。本轮继续落实 [D08 / M04 设计](DESIGN.md)，补齐 [上轮视觉复核](SCENE_REVIEW.md) 确认的阅读页缺口。手机按固定字号，只在 macOS 中渲染生产组件，没有测试实体 iPhone。

## 阅读行为

- 原生分页输出左侧显示一基行号；过滤后保留非连续的原输出索引，横向滚动时行号固定。仍只有一个纵向列表，不为行号增加独立滚动位置。
- 底栏显示当前可见行范围、保留总量及过滤状态。选段后直接显示“将所选 N 行附给 AI”；过滤后的数量只包含实际显示并附加的行。
- 查找入口及 Cmd/Ctrl+F 打开独立查找栏。大小写不敏感的文字查找保留上下文，不改动过滤或用户选区；显示匹配行数量，支持上一行、下一行及首尾循环，Esc 只关闭查找。
- 查找以最多 128 行一页读取原生输出，页间让出事件循环；新查询或退出阅读页取消旧扫描。输出更新保留当前匹配及阅读锚点；源范围淘汰时按来源偏移重定位，不能读取时丢弃不完整结果。
- 短屏合并范围和匹配数量，收紧外侧留白，保留 48px 的附加按钮。180px 可用高度下，查找和选段同时存在时仍有 36px 的输出区；320px 高度下有 114px。

“匹配行”按物理输出行计数，并高亮整行；没有把一行内多个相同词算成多个结果。复制及附加仍使用独立的原始选区，查找不会替用户选择或发送内容。

## Vim 执行回执竞态

完整原生流程曾停在“审批后返回终端”。单次重跑通过不能排除缺陷，因此增加受控回归：让 Vim 先退出 alternate screen，再返回已批准按键的执行回执。原代码只看当前屏幕，稳定复现未关闭 AI 覆盖层；修复后同时依据提案批准时的原始目标。一次回执只交还一次输入，重新打开旧任务不会再次关闭。

见 [修复前失败](evidence/reader-tools/tui-return-race-before.log)、[应用回归](evidence/reader-tools/reader-tools-app-final.log)及[真实 Vim 流程](evidence/reader-tools/reader-tools-native-final.log)。按键仍只在用户审批后发送，没有重试输入。
