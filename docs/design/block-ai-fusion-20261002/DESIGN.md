# Trail：Block 与 AI 融合交互设计

日期：2026-10-02。基于当前 `composer` 分支的实际能力、既有审美取舍及 Warp 官方文档。本文和配套 imagegen 图是待实现的设计方案，不是产品已实现或已通过运行验收的声明。

## 目标与取舍

把「用户目标 → 上下文 → 可审阅动作 → 真实执行 → 可引用结果 → 下一步」放进同一条可追溯流程。保留终端的精确输入和输出，把 AI 作为有状态的协作者。普通执行无需出现额外 AI 面板；进入任务后，问题、解释、提案和真实命令块按时间排列，替代当前右下角浮动对话框。

既有约束全部保留：桌面整块默认不超过终端可用区域的 1/3；手机最多 6 行预览并有独立阅读页；真实 Terminal 渲染输出；SSH 按当前节点协商，失败自动 Normal、恢复手动 Blocks；模式入口为 tab 右键或触控会话菜单；手机平台默认 Blocks；top/vim 等全屏程序占用完整可用 terminal。

## 四组独立状态，避免把所有事情都叫「模式」

1. **会话显示**：Blocks / Normal，由当前能力与用户选择共同决定。入口在 tab／会话菜单。
2. **输入意图**：命令 / AI 提问，始终以文字和主操作区分。切换只改变输入去向，不能执行或切换显示模式。
3. **执行归属**：shell 就绪 / 普通运行命令 / TUI / 用户接管 / 已断开。一个 PTY 同时只有一个输入所有者。
4. **AI 任务**：草稿 / 澄清 / 思考 / 待审批 / 提交中 / 观察中 / 暂停 / 需恢复 / 已完成。命令运行时 AI 可以暂停；模型有回复时任务未必完成。

会话内任务保留原始目标、追加约束、消息、命令引用、待批 revision 和阅读位置。任务切换不启动第二个后台执行器。退出应用后的任务持久化、云端任务同步、自动批准均不属于本方案默认能力；若未来增加，需另行设计。

## 空间结构

- 顶部保留现有应用 chrome 与 session tabs。AI 任务打开时显示一行任务面包屑，可返回终端或选择本会话任务。
- 主区只有一条时间线。普通块由命令、输出、状态组成；AI 解释为正文；提案在执行前显示可审阅边界，接收后原位关联真实块。
- 状态条固定在 Composer 之上，仅表达当前任务与必要恢复／定位入口。不能在看不到完整提案时直接批准。
- Composer 沿用环境、编辑、操作三层结构。命令补全／历史与 AI 附件工具按输入意图出现；两个草稿分别保留。初次选块是待附加上下文，提交后才变成任务证据。
- 宽屏保持同一内容列，不自动创建聊天侧栏。输出阅读器可暂时扩展；短窗口状态并入任务标题。移动端审批与输出阅读用专用页面，正常列表避免双层纵向滚动。

## 布局与视觉 tokens

复用 `IanvsTheme`、`AppThemeTokens`、`ComposerTheme` 与已许可的 outline 图标。浅色为安静底色、冷灰 chrome、深墨正文、蓝色单一主操作；深色为 charcoal/raised surface，使用配对前景色。错误、警告、运行都同时带文本或形状，不只依赖颜色。

间距 4/8/12/16/24；控件圆角 6、dock 12；正文 14–16，命令约 14、行高约 1.5，状态 12。默认边界 1px，高对比增强；编辑器沿用 caret-only focus，按钮／菜单保留可见键盘焦点。桌面点击目标至少 32，触控至少 44。长警告可换行，不把关键原因截断。

宽度 >= 960 采用完整环境行与文本操作；600–959 合并次级 metadata，保留所有入口；<600 单列、次要动作进入菜单。断点最终应由实际字体测量和可用约束调整。桌面 2× 文字不全局压缩，优先换行与缩短 metadata；手机设计、实现和验收只考虑固定字号，不要求跟随系统字号、动态文字缩放或大字号适配（见根目录 AGENTS.md）。横屏／短窗保持主操作可见。

桌面默认块高：`max(0, floor((H_terminal/3 - H_header - H_status - H_padding)/lineHeight))` 行输出。标题状态不可被压掉；若剩余不足一行，改为折叠行 + 查看全部，而不是溢出。手动扩大属于该块的阅读偏好，不受后续输出刷新重置。手机按最多 6 行自然高度，和软键盘高度解耦。

## 行为合同

**滚动**：用户手动回看暂停跟随；输出更新不重建 ScrollController，不取消惯性、不以 hover 强制 reveal。桌面边界可把剩余 wheel delta 交给外层；手机预览不拦截纵向拖动，全屏 reader 单滚动。锚点使用 blockId/lineId 和像素偏移，分页插入补偿。只有显式「回到最新」恢复跟随。

**焦点与快捷键**：Cmd+I 进入／切换 AI 意图并保留草稿；Enter 遵循当前明确主操作；Shift+Enter 换行；IME 组词时 Enter 不提交；Tab 保留命令补全采用语义，采用不执行。Esc 按最内层弹层→reader/任务视图→输入的层级关闭，不能同时发送给 TUI。Ctrl+C 只在终端拥有焦点时发送。审批按钮必须获得焦点或被明确点击，不把全局 Enter 当作批准。

**审批与恢复**：提案绑定 sessionId/contextId/cwd/lease/revision。用户编辑、目标变化、手动输入或暂停都会撤销未执行批准。输入提交确认与命令退出分开。未知结果只检查原提交，不自动重发。继续任务先读新状态，保留原目标和约束；任务结束应由证据支撑，退出码 0 只证明对应命令的结果。

**上下文**：块引用含 id、命令、cwd、状态、原生输出范围、总行数、是否截断／淘汰。用户可审阅附加范围。自动读取限定当前任务相关结果；截断明确告知，必要时可提议读取指定范围。未来 range-read 工具应是只读、有上限、有来源，不用 shell 重跑命令模拟历史。仅去掉完全重复观察，不能丢掉唯一证据或用户约束。

**SSH**：握手能力只属于当前节点；协商时输出仍可用。自动降级保护可见输出和同一 PTY。首次成功按偏好启用，降级后的能力恢复只提示；手动选择通过桌面 tab 右键／触控会话菜单。Normal 下 AI 仍可按实时屏幕提供经批准的按键，不伪造 block 边界。

**可访问性**：关键状态使用温和 live region，仅在阶段变化播报；不要每行输出都播报。命令、来源、退出码和范围可被朗读。选择块与选中文本语义独立；菜单可键盘退出且焦点回到触发点。Reduce Motion 关闭装饰动画；高对比和桌面2×字号有独立验收，图像稿本身不能证明合规。

2026-10-03 验收范围调整：用户明确要求跳过 VoiceOver。本次不以实际 VoiceOver 朗读作为完成条件，并将该项保留为未验收；上述语义、键盘、高对比与减少动态效果要求仍保留。当前实现与证据见 [CURRENT_ACCEPTANCE.md](CURRENT_ACCEPTANCE.md)。

每个场景都有独立设计图、完整 imagegen prompt、详细流程和验收条件。`scenes.json` 是对应索引；图像中示例命令和结果均为 mock 数据，不代表本仓库真实执行结果。图像文字如与本文冲突，以行为合同和场景正文为准，并在视觉复核中记录。

### D01 统一输入与待附加上下文

入口：完成块「询问 AI」或 Cmd+I。主要动作：发送给 AI。出口：D02；缺少配置进入 D14 后返回草稿。

从已完成块的「询问 AI」或 Cmd+I 进入；保留命令草稿与选区。选择块只进入待附加上下文，发送后才固定为该任务的输入。用户可移除上下文；自然语言识别仅建议 AI 意图，显式覆盖在当前草稿内保持。发送按钮明确写「发送给 AI」，不能把自然语言发给 shell。

验收：切换意图不执行、不丢草稿；IME 组词 Enter 不提交；附件范围可查看；首次无配置转 D14 并保留草稿。

### D02 任务建立、澄清与计划

入口：新任务存在目标或约束歧义。主要动作：发送补充。出口：解释结果 D05，或提出可审阅动作 D03。

新任务获得会话内 taskId、原始目标、约束和所附块。有实质歧义时先澄清；答案写入同一任务。计划是可修改的说明，不是命令授权；明确「只分析」后不能擅自给出自动修改。简单问题直接解释，不强制计划页。

验收：澄清不写 PTY；计划更新保留用户约束；取消保留草稿；无依据不显示已完成步骤。

### D03 命令提案审阅与单次执行

入口：模型返回未执行提案。主要动作：执行一次。出口：收到提交回执进入 D04；目标改变进入 D09；回执未知进入 D10。

提案包含用途、精确目标、目录与完整命令／命名按键。编辑后生成新 revision，废弃旧审批；拒绝只记一条拒绝事件。执行一次冻结 revision，获取最新 session/context/lease 核对后提交；双击只产生一个 submissionId。

验收：目标变更撤销确认；命令不省略不可见后缀；审阅区内 Enter 不隐式执行；键盘焦点到执行按钮才触发；多条提案逐条确认。

### D04 执行、等待与新输出

入口：已批准动作收到提交回执。主要动作：补充要求；必要时暂停 AI。出口：命令完成进入 D05／D06，需恢复进入 D09／D10。

提案原位关联同一真实块，状态为提交中→运行中→已退出；接收回执不等于命令成功。AI 等待是单独状态，限时读取但不重复提交命令。输出到来时跟随仅限用户本来在底部；手动回看立即暂停跟随。「补充要求」只更新同一任务约束，不向 PTY 写入；取消旧推理、撤销未执行提案，下一轮读取新状态并采用追加约束。已提交命令不会因此中断。

验收：暂停 AI 不发 Ctrl+C；「中断命令」是独立显式操作；长期静默显示已等待时长与最后输出时间，不伪造进度；整个桌面块默认不超过可用视口 1/3。

### D05 结果、证据与继续追问

入口：命令退出且结果可核实。主要动作：继续提问。出口：沿用任务进入 D02／D03，或返回终端。

命令退出后由实际退出码和可见证据驱动总结；总结引用 blockId 和输出范围。点击证据定位原块而非复制出第二块。任务完成恢复输入焦点但不抢走用户阅读位置；追问默认沿用同一任务约束，明确新任务才重置。

验收：退出 0 不等于需求完成；区分模型推断与命令证据；总结注明验证范围与截断；无输出命令仍可根据退出码说明。

### D06 失败诊断与修正提案

入口：真实命令非零退出，用户提交诊断请求。主要动作：审阅修正提案。出口：新提案 D03；原失败块永久保留。

错误块快捷入口只附加该块并打开 AI 草稿，不自动发送修复。发送后先解释错误和依据，再提出新的修正命令。原失败块永久保留原始状态；修正执行另建块并关联来源。对环境、凭据等问题不得编造可直接重试的修复。

验收：纠正按钮不执行；没有规则或证据时明确不足；原输出、命令及退出码不被新命令覆盖；重复失败回到诊断。

### D07 选择多个块作为 AI 上下文

入口：从块标题选择一个或多个块。主要动作：附给 AI。出口：D01 的待附加区；发送后成为固定证据。

块选择、文字选择与附件是三个状态：单击标题选块，拖动输出选文字；Cmd 多选、Shift 连选。点击「附给 AI」生成待附加引用。默认当前会话；跨会话资料需显式选择且清楚标源，不能成为执行目标。发送时冻结输出版本与范围。

验收：移除附件不删除命令块；显示末尾 160 行、总量、淘汰或不完整；只有用户确认的上下文发送；手动选择片段可替代整块。

### D08 长输出阅读、搜索与引用

入口：桌面块「查看全部输出」。主要动作：将所选行附给 AI。出口：返回任务并恢复草稿、选区和历史位置。

展开桌面块进入受约束的大阅读区；标题固定，分页读取真实终端保留行。行内查找、过滤只影响展示，默认复制原始完整保留输出；复制所选／过滤结果必须明确命名。选择行后作为带来源范围的附件，返回恢复草稿和列表锚点。

验收：一次纵向手势只有一个滚动归属；到边界可继续滚动外层；新输出不拉回；范围淘汰明确提示不可读取；扩展内容不能假装已经全量发送 AI。

### D09 暂停、接管与目标变更

入口：手动接管、暂停或执行目标变化。主要动作：读取新状态后继续任务。出口：同目标观察 D04；新目标重新提案 D03。

用户输入、暂停、关闭任务视图或目标改变均撤销尚未执行提案；已执行命令继续运行。继续任务先读新状态，保留原目标与约束。当前 session/context 不同，必须明确选择回到原目标或基于新目标继续，旧批准不能迁移。

验收：恢复不重复已提交命令；双击恢复只启动一轮；用户接管过程中不发送晚到模型指令；关闭视图与终止任务语义分开。

### D10 未知执行结果与连接恢复

入口：断线、请求失败或提交回执未知。主要动作：重新连接并检查。出口：确认原命令结果后 D04／D05；仍未知保持人工检查。

区分模型请求失败、终端断线、提交结果未知和正常等待超时。模型失败可继续观察；提交未知不能自动重发。重连后先查询原 submission/block，再给可确认结果；仍未知提示人工检查。认证错误转配置页并保留任务。

验收：错误不吞目标／草稿／历史；原命令提交计数不变；取消网络请求不会回滚 PTY；连接恢复不自动授予新动作。

### D11 SSH 协商与显示模式回退

入口：当前 SSH 节点能力失效／协商中。主要动作：tab 右键查看模式与原因。出口：Normal 保持可用；能力恢复后用户手动选择 Blocks。

每次 SSH／嵌套 shell 按当前节点协商能力，握手期间继续显示原终端输出。失败自动 Normal，tab 显示原因；初次成功依新会话偏好启用 Blocks，已降级后的恢复只通知可切回。桌面右键 tab／手机会话菜单手动选择；重检不重连、不静默写配置文件。

验收：外层 shell 能力不能用于内层；降级不丢输出／草稿／同一 PTY；AI 上下文更新节点且撤销旧提案；不能使用 block 时仍允许读取当前屏幕与审阅按键。

### D12 全屏 TUI 与 AI 输入交接

## 事件与状态转换

输入来源和会话目标优先于模型回复。任何有写入效果的动作都必须先通过当前 revision 和目标核对；晚到推理不能重新激活已撤销的提案。

| 事件 | AI 任务变化 | 终端变化 | 用户看到什么 |
| --- | --- | --- | --- |
| 发送问题或澄清 | 草稿／澄清 → 思考 | 不写 PTY | 问题与固定上下文进入时间线 |
| 返回命令提案 | 思考 → 待审批 | 不写 PTY | 完整目标、命令和单次执行入口 |
| 批准当前 revision | 待审批 → 提交中 | 至多提交一次 | 先显示提交中，收到回执后关联真实块 |
| 收到提交回执 | 提交中 → 观察中 | 命令可能仍在运行 | 块运行状态与 AI 观察状态分列 |
| 有新输出／等待到期 | 保持观察或给出有依据的下一步 | 不重复命令 | 更新结果；等待到期本身不是命令失败 |
| 命令退出 | 观察 → 总结或新提案 | 记录真实退出码 | 原块结果固定；下一条动作仍需审阅 |
| 补充要求 | 取消旧推理、撤销待批提案，读取新状态 | 已提交命令继续 | 约束追加到当前任务；无 PTY 输入 |
| 暂停 AI／用户手动输入 | → 暂停或用户接管 | 暂停不发送 Ctrl+C；用户按键按当前所有权处理 | 区分“AI 已暂停”和“命令仍在运行” |
| 中断命令 | 等待中断结果，不直接写成功 | 向明确的当前命令发送中断 | 命令的真实退出状态随后到达 |
| 目标／cwd／lease 改变 | 撤销旧提案 → 需恢复 | 保留现有终端 | 明确原目标与新目标，继续前重新读取 |
| 提交回执未知 | → 需恢复 | 不自动重发 | 重新连接并检查原 submission |
| SSH 能力丢失 | 撤销受影响提案、核对上下文 | 同一 PTY 自动 Normal | tab 提示原因；能力恢复后手动切回 |
| TUI 接管 | 保持观察或暂停，变更输入所有权 | 完整终端网格 | 终端原生输入；AI 页面覆盖不 resize |
| 手机进入后台 | 暂停新的模型动作 | 不承诺后台持续连接 | 回前台先核对，再提供继续入口 |

在补充要求到达与动作提交竞争时，以实际提交边界为准：尚未提交的 revision 立即失效；已经提交的动作展示“已提交，补充要求将用于下一步”。不能用界面取消假装撤回已经交给 PTY 的命令。同一 submission 的所有回执只关联一个 blockId。

## 典型路径与异常路径

- 桌面分析与修复：D01 → D02（仅有实质歧义时）→ D03 → D04 → D05；非零退出保留原块并进入 D06。
- 基于历史提问：D07 → D01；需要精确片段时 D08 → D01。新提案到来使用 D13 明确定位。
- 暂停与恢复：D04 → D09 → 读取新状态 → D04／D05／D03；提交未知走 D10，绝不通过恢复按钮重跑原命令。
- SSH／全屏程序：D11 或 D12 保留同一 PTY；退出并恢复能力后只提示手动切回 Blocks。
- 手机：M01 → M02 → M03；长输出 M03 → M04 → 原位置；失去能力 M05；全屏程序 M06。
- 首次缺少 AI 配置走 D14，再回原草稿；普通命令与 Normal 始终可继续使用。

## 当前差距与实施顺序

本设计未修改产品 UI。当前代码已有同一 PTY 的 AI bridge、逐次审阅、等待／恢复、块范围元数据与模式回退；以下仍是实现工作，不能从图像推断已存在。

1. **统一状态和证据**：任务保存原始目标、约束、命令引用及输出范围；将命令运行、模型等待、提交未知分开。优先建立事件归属与 submission 幂等边界。
2. **主时间线与审批**：替代浮动 AI 面板，提案与真实块通过 id 关联；新增提案不抢阅读位置；可跳转审阅、回原位置。补充约束要撤销旧推理与提案。
3. **上下文与输出读取**：当前 AI 使用块末尾最多 160 行，尚缺任意范围分页读取；新增只读 range API、选择范围与固定引用版本，并清楚反馈淘汰和截断。
4. **手机页面与空间**：列表预览、完整审阅、输出阅读及 TUI 是不同空间；取消手机嵌套纵向滚动，按真实行高和键盘约束布局。
5. **场景验收**：先做故障可复现的执行／恢复回归，再验证主时间线和滚动，最后做真实模型任务比较。视觉稿不可作为行为测试替代品。

近期问题依据见 [AI 行为验收记录](../../ai/ACCEPTANCE.md) 与 [Terminal-Bench UI 报告说明](../../ai/TERMINAL_BENCH_2_1_UI.md)：12 秒命令旧循环耗尽 24 次请求，更新后的固定响应服务场景降至 3 次；这证明该等待回归被修正，不能外推为真实模型提速八倍。相同三项代表任务、三个模型的最新结果为 Normal 与 Blocks 各 7/9；整体模式样本数不同，且有网络与评测中断，不可直接把总分或墙钟时间当作模式性能差异。
