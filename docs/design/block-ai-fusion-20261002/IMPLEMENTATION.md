# 场景实现跟踪

目标：在当前 composer 分支完整实现 DESIGN.md 的 20 个场景。设计稿和图库校验不是实现验收。保留当前工作区已有修复，不提交或推送未经要求的改动。

当前逐项状态以 [CURRENT_ACCEPTANCE.md](CURRENT_ACCEPTANCE.md) 为准。以下保留实施过程与各轮当时的待验事项；最新 Block／Shell 动态效果和独立原生验收见 [MOTION_REVIEW.md](MOTION_REVIEW.md)。2026-10-03 用户明确要求跳过 VoiceOver，实际朗读记为未验收，其余场景实现与验收已完成。

## 实施顺序

1. 任务、固定上下文、提案 revision、提交与块引用；只读范围读取；恢复与目标变化。
2. 用同一真实块组件构建主时间线，替代浮动聊天窗；统一输入意图、草稿和附件。
3. 桌面阅读、审批编辑、回看与跳转；手机专用审阅／阅读、背景暂停；Normal／TUI 保持完整网格。
4. 逐场景行为、布局、可访问性基础、真实 macOS 流程验收；同步发布包镜像。手机使用组件／模拟场景，遵从用户不再测手机的要求。

## 恢复与提交归属修复

- 原生验收发现：Composer 轮询到 AI 的短暂 `submitting` 后，把外部提交当作自己待确认的回执，即使原生 shell 已 ready 仍锁住编辑器。新增失败复现后，改为仅有自身 `pendingSubmission` 时保留提交锁；自身 pending/unknown 仍不能被 shell 轮询解锁，不增加自动重发。
- 未知提交的检查按 task 去重，晚到检查不能覆盖新任务。终端恢复只清除终端错误，不会擦除独立认证错误；显式 Ctrl+C 遇到断线同样提供只读检查入口。
- 原始失败和修复后日志已留存，见 BEHAVIOR_VALIDATION.md。没有提交或推送。
