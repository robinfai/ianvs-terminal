# D05 历史证据来源与淘汰定位

2026-10-03，`composer` 工作区，macOS 27.0.1（26A434）。落实 [D05 / D08 行为合同](DESIGN.md)：引用必须打开当时提供的原始证据，不能在输出淘汰后误读新的相对行号。

## 修复

原先回复只保留块 ID、来源会话和相对行范围，点击时进一步缩成 ID 与起始行。保留缓冲区前端被释放后，相同相对索引可能已经对应另一行；重连后若出现相同原生块 ID，也不能通过扫描当前所有块来猜测来源。

现在把模型请求中实际包含的 `source_line_base` 与来源会话、完整范围一起冻结，贯穿回复按钮、连接路由和原生阅读页。引用只依据当时发送的结构化证据，不再回查当前最后一个块来推断历史来源。

- 原行仍在：按冻结的来源基准换算当前位置，行号栏与范围继续显示引用时的行号；内部选区和复制仍使用当前原生坐标。
- 部分或全部引用行已释放：显示“引用的输出范围已不可读取”，不会把剩余片段冒充完整引用，也不会夹取边界后定位别的行。
- 同一编号与范围对应多个来源／历史版本：显示无法唯一定位，要求从原块重新选择；不会自行选一个版本。
- 重连后原连接仍保留：直接使用引用的来源会话，避免相同块 ID 的碰撞。
- 保存过的过滤不隐藏引用起点。引用页先显示原始输出，用户可再手动启用已保存的过滤；退出不会删除其过滤设置，复制所选也不会暗中套用未启用的过滤。

关闭键盘与创建路由之间仍可能产生输出，所以范围在阅读页建立后重新核对。分页也验证来源基准；跨版本回复不会拼在一起。若分页期间基准变化，但引用行仍保留，下一次刷新重新恢复引用位置；若已释放则显示不可读取。已经打开的引用页遇到后续淘汰也遵守相同规则。

## 真实 PTY 证据

独立测试建立临时 HOME 的真实 zsh 与 600 行滚动历史，只执行三条预设 `seq` 命令。模型回复是确定性夹具，AI 端口只读，不是模型质量评测。

先从实际原生输出冻结第 411–413 行，再增加 200 行输出。原生基准由 1 变成 171，引用起点由相对索引 410 换算为 240；实际阅读锚点约 239.65，前一行部分可见，目标文本仍为 `411`，行号栏也显示 `411`。随后增加 800 行，原范围被释放，点击同一引用只显示不可读取。两次点击没有额外模型请求或 AI 写入。

查看[保留范围截图](evidence/evidence-identity/native/D05-retained-native-source.png)、[释放范围截图](evidence/evidence-identity/native/D05-released-native-source.png)及[原生结果](evidence/evidence-identity/native/result.json)。没有恢复已经淘汰的文本，没有复制出新的执行记录，也没有重新运行旧命令获取历史。

## 回归与发现

9 项引用导航回归覆盖桌面／固定字号手机、保存过滤、原始选区复制、点击前／关闭键盘／分页期间淘汰、部分范围释放、多版本歧义、分页恢复和重连后的块 ID 碰撞。

扩大测试时发现普通过滤阅读的 `initialRow` 被错误当作原始索引转换。现已限定为显式引用路径；普通过滤阅读仍按显示行序号恢复，29 项复制回归恢复通过。Shell 对外使用工作区公开的引用类型，架构的依赖与行数限制保持不变。

最初独立原生夹具缺少生产 Composer 对提交准备／回执的轮询，导致首条命令没有完成提交。已补齐相同协议轮询并重新创建独立会话；没有重试状态未知的旧提交。失败日志保留在证据中。

最终验证：850 项应用回归、76 项共享终端回归、9 项引用导航专项、1 项真实 PTY 淘汰及 5 项原生全流程／手机组件测试通过；专项包含在应用计数中，不重复累计。静态检查无问题，发布镜像无漂移。归档包含 23 项证据和 15 个源码哈希，见[清单](evidence/evidence-identity/manifest.json)。原生及应用测试后只简化了阅读页状态的三处布尔／空值判断，随后重新通过静态检查和共享终端回归。手机只做固定字号组件验证，没有实体 iPhone 验收。本轮未运行外部模型、OAuth 代理或真实远端 SSH。

本项补齐了上轮记录的历史引用定位缺口。完整 20 场景审计、D10/D13/D14 最终视觉复核及真实目标节点复验仍继续，不能将本项通过作为整个目标完成。
