# AI 消息与审核流程复核 · 2026-10-04

当前 `composer` 工作区在自动审核／待确认生命周期修复后，完成五轮内置 imagegen 审查和实际运行复核。第四、五轮共十个画面没有可确认的新视觉问题。结论限定于下面列出的状态与平台；生成审查图会重画或裁剪界面，实际截图、状态断言和执行回执才是验收证据。

## 本轮改动

- 对话采用同一左对齐轴，明确标注“你 / AI”；用户消息使用中性浅底，AI 正文保持平面布局。正文最大宽度 960pt，命令块维持可用全宽。
- 角色标签使用主题文字色。测试发现旧深色蓝色标签对比度仅 3.09:1，已修正；浅深色标签均通过 4.5:1 检查。Markdown 链接使用主题可读操作色和下划线。
- 审批记录区分待确认与历史状态。已确认但提交结果未知时显示“已由你确认”；撤销／拒绝后显示审核记录；历史记录不再声称“尚未发送命令”。未知回执仍禁止自动重发。
- 手机提案卡直接提供“拒绝”，执行仍需进入完整审阅。320pt 和 390pt 下点击拒绝均不进入审阅页、不产生终端输入。
- ACP 参数验证失败原先只返回 `invalid_action`，丢失了可修正原因。现在仅对输入前的 `AiInvalidAction` 返回本地校验说明和 `submitted: false`；未知提交等错误仍要求检查原回执，不允许据此重发。
- 原生证据截图等待页面转场结束，避免把动画中间帧误判为页面重叠。没有为此修改导航行为。

此前的自动审核问题及修复见 [SMART_APPROVAL.md](../../ai/SMART_APPROVAL.md)：旧配置缺少 `approvalMode` 时沿用每次确认；ACP 提前结束又把待确认阶段覆盖为 idle，导致按钮消失。当前保留宿主审批状态，批准后以原回执继续 agent，不重复提交。

## 五轮审查

| 轮次 | 核实与处理 |
| --- | --- |
| 1 | 接受消息角色区分和阅读宽度建议。未采用生成图发明的时间戳、额外侧栏或简化输入区。 |
| 2 | 复查深色、手机、桌面 2 倍字号和提案。所谓“右上角红色标记拥挤”是生成图自己的标注，原截图没有该控件。随后实际测试发现并修正标签对比度和未知提交文案。 |
| 3 | 接受手机拒绝路径多一步的问题，增加直接拒绝。设置 Save 按钮在原图完整显示且能点击，不采纳裁切误报；未知结果是实际状态，保留明确说明与原回执检查入口。 |
| 4 | 手机提案、完整审阅、真实 ACP 结果、证据页、Vim 输入审阅均无可确认的新问题。 |
| 5 | SSH 降级菜单、连接测试后未保存、手机深色阅读器、极短横屏、未知提交恢复均无可确认的新问题。 |

审查图为 `01-message-direction.png` 至 `05-recovery-and-compact-review.png`；完整提示词在 [prompts](prompts/)，逐项判断在 [triage.json](triage.json)。全部使用内置 imagegen，没有使用 CLI fallback。

## 失败记录及边界

- 初始 ACP 原生回归收到模型的 `invalid_action` 后没有生成提案；原日志保留于 `09-real-acp.log`。当时服务端丢弃了具体参数原因，无法追认是哪一字段无效。补充类型化校验反馈后的一轮真实对话通过；这不证明未来模型不会再产生无效参数。
- 深色标签对比度失败已由新颜色和最终回归验证解决。短横屏测试最初把手势拖出整个窗口；改为窗口内可执行手势后回看通过，没有宣称因此修复了生产滚动代码。
- 手机 Shell 测试的模拟后端未提供 `commandNames`，在新的自动意图规则下无法证明 `echo` 是命令。补齐模拟清单后两平台回归通过，没有放宽未知输入的生产路由规则。
- 早期编译／格式错误和失败日志均保留；最终判定使用表中成功运行，不把旧失败隐藏或当成通过。
- 实际原生平台仅 **macOS 27.0.1**。手机是固定字号生产组件／原生渲染器预览；按用户指令跳过物理 iPhone、VoiceOver。本轮未重新连接真实 SSH 节点，模式测试是受控协商状态；未重跑 Terminal-Bench，也未覆盖其他受支持 OS 的实机。
- 部分 `modes` 组件截图里的共享终端中文页脚使用测试等宽字体后显示方块；不能作为真实原生字体效果的证据。最终视觉复核使用字形完整的模式菜单与原生阅读器截图。
- 未关闭用户现有 SSH 窗口，未替换日常安装版，未提交或推送。构建路径为 `example/build/macos/Build/Products/Debug/Trail Development.app`。

本轮源文件和证据哈希见 [manifest.json](manifest.json)。
