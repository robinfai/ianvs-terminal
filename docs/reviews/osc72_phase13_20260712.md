## Findings and resolution

| Finding | Resolution |
|---|---|
| OSC 72 was classified only as generic custom data | Added a separate default-off drag/drop intent and capability |
| No typed child-command model existed | Added all 13 `t` actions, 32-bit metadata validation, payload bounds and retained-byte accounting |
| Replying to `t=q` could falsely claim unavailable source drags | Product replies only when the native target bridge is installed and reports `drop=1:offer=0` |
| Background sessions could compete for the window target | Only the active pane is registered; switching panes synchronizes saved target state |
| Native Finder data had no safe lifecycle | Capture only after a user drop, cap at 64 MiB, read in 3,072-byte chunks and release on completion/error/reset/exit |
| Empty MIME lists were initially treated as disabled | Fixed to the protocol defaults `text/plain` and `text/uri-list` |
| Remote URI sub-item requests could be confused with local MIME indexes | `y/Y` requests are rejected with `EINVAL`; no host file is read |
| Legacy insecure filtering did not know the new capability | The compatibility safety switch now explicitly denies OSC 72 |

## Final Computer Use gate

The live Debug app accepted a real child probe, visibly printed
`OSC72-COMPUTER-READY`, and returned the exact correlated response
`t=q:i=8;drop=1:offer=0`. This proves that the production PTY, parser, product
controller and native target registration are connected in the running app.

Computer Use's single drag action releases before OSC 72's asynchronous
child-negotiation round trip can be held and observed, so this review does not
claim a visually observed Finder copy cursor or dropped URI. That gesture is
covered by the product controller tests, native pasteboard/operation XCTest,
application real-PTY lifecycle and the repository gate above. The accepted
final threshold is therefore composite: visible production query/registration
through Computer Use plus deterministic automated move/drop/data evidence.

## Compatibility and rollback

The new session config field defaults false, native events are additive and no
frame/protobuf schema changes. Reverting the Phase 13 implementation returns
OSC 72 to a bounded no-op. No outgoing drag, remote file read, directory walk,
symlink traversal or arbitrary host path authority is introduced.
