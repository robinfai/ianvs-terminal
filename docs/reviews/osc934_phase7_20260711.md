# OSC 934 Phase 7 governance review — 2026-07-11

## Outcome

Phase 7 is complete in native commit `66016b4` and product integration commit
`189dee9`. The protocol is identified as the Ianvs/private capability
`ianvs-osc934/1`; it is not attributed to xterm, iTerm2, Kitty, WezTerm,
Windows Terminal or VS Code.

The normative grammar, lifecycle, versioning, limits, unknown-field behavior,
error behavior and security contract are in
[`ianvs_osc934.md`](../protocols/ianvs_osc934.md).

## Implemented contract

- canonical query: `934;query`;
- static ST-terminated capability response with no session data;
- no response loop when a capability response is received as input;
- 8 KiB streaming and parser payload boundary;
- 1–128 byte IDs, 1–1,024 byte labels and 64 retained IDs per session;
- retained IDs remain updateable/removable at capacity;
- canonical typed-event source `ianvs_osc934`;
- diagnostics and Debug output omit ID, label and payload text;
- presentation policy only: no clipboard, file, URL, command, process or OS
  notification authority.

## Automated evidence

Parser, terminal, native session and Dart tests prove set/update/remove/
remove-all, malformed and unknown properties, duplicate properties, query,
response-loop prevention, capacity behavior, stable source identity, VT220 and
policy gates, streaming overflow discard and diagnostic redaction. The final
strict repository gate is recorded in `osc_protocol_changes_20260711.md`.

## Cross-terminal status

No external terminal is claimed to implement this private protocol. Attempts to
collect iTerm2 3.6.11 and Ghostty 1.2.3 UI evidence were rejected by the Computer
Use safety boundary for terminal emulators. That restriction was not bypassed;
the exact status is recorded in `osc_cross_terminal_probe_20260711.md`.
