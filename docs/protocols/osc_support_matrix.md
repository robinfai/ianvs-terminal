# OSC support matrix

Status reflects product behavior and repository evidence on 2026-07-14. A
dispatcher arm, enum variant, or parser function by itself is not evidence of
product support.

Evidence labels:

- **covered**: an automated assertion exercises the stated behavior.
- **gap**: implementation exists, but the named layer has no targeted assertion.
- **N/A**: that layer is intentionally absent (normally for a no-op/deferred protocol).
- **pending**: the manual GUI or reference-terminal run has not been executed.

`Host smoke` distinguishes real-PTY tests from the final GUI/reference-terminal
acceptance. The latter remains pending unless explicitly stated; this matrix does
not infer interoperability from `$TERM` or from Ianvs-only tests.

## Deferred phases and acceptance boundary

- **Phase 8 / OSC 99** established the bounded display/lifecycle subset.
  **Phase 31** promotes only report activation, label-only buttons, tracked
  in-window close reports, default-ID semantics and alive queries. Protocol
  focus, sound, icon transfer, urgency and command actions remain unsupported
  and unauthorized.
- **Phase 9 / OSC 3008** typed metadata is implemented. It intentionally has no
  visual UI and cannot authorize host behavior.
- **Phase 11 / OSC 22** pointer shapes are appearance-only; they cannot move the
  host pointer, capture input or authorize host actions.
- **Phase 12 / OSC 66** sized text is appearance-only; fixed/natural widths,
  scale, alignment, grid edits, scrollback, resize and rendering are covered.
- **Phase 13 / OSC 72** implements a user-driven macOS drop-target subset.
  Outgoing drags, remote URI entry reads and directory traversal remain deferred
  as separate host-action/file-authority capabilities.
- **Phase 14 / OSC 1337 metadata** implements SetMark,
  ShellIntegrationVersion and an accurate logical ReportCellSize response.
  Upload/download, focus, URL, profile and custom actions remain separate and
  unauthorized.
- **Phase 15 / dynamic cursor shape** implements OSC 1337 CursorShape and
  exports existing DECSCUSR shape/blink state through additive cursor fields.
  It also removes the prior DECSCUSR warning-bell-volume side effect.
- **Phase 20 / OSC 5522** extends the binary/MIME clipboard core with exact
  session-scoped password/application caching, paste-event notifications,
  DECRQM state and short-lived single-use read tokens. Non-macOS primary-
  selection integration remains deferred.
- **Phase 21 / OSC 21337** implements bounded session-local tab presentation.
  It is appearance-only and cannot authorize host actions.
- **Phase 22 / OSC 1337 ClearScrollback** implements iTerm2's prompt-preserving
  Clear Buffer behavior and synchronizes native replay/cache state. It is
  terminal-local metadata and cannot authorize host actions.
- **Phase 23 / OSC 1337 HighlightCursorLine** implements iTerm2's session-local
  cursor guide through the existing theme and cursor frame paths. It is
  appearance-only and cannot authorize host actions.
- **Phase 24 / OSC 1337 clipboard write** implements direct Base64 text copy and
  legacy streaming capture through the existing policy-gated clipboard path.
  Parser acceptance never authorizes a pasteboard write.
- **Phase 25 / OSC 1337 annotations** implements visible and hidden bounded
  terminal-range notes through the existing per-session annotation product UI.
- **Phase 26 / OSC 1337 blocks** implements nested `Block` lifecycle marks and
  `UpdateBlock` fold/unfold through non-contiguous row virtualization across
  scrollback, rendering, search, selection, graphics, resize and replay. It is
  terminal-local layout state and grants no host authority.
- **Phase 27 / OSC 1337 block rendering** adds the `render=1` text-document
  projection: Markdown/JSON/plain/code classification, theme-derived syntax
  runs, search/selection continuity, close-to-restore, additive frame state and
  resize-replay preservation without adding host authority.
- **Phase 28 / OSC 1337 file download** promotes only incoming non-inline
  `File` and multipart transfers. Bytes remain in bounded native one-shot
  storage until the active pane's user selects Save; cancel, timeout, invalid
  metadata and background delivery discard them. `RequestUpload` is denied and
  cannot disclose local files.
- **Phase 29 / OSC 1337 OpenURL** promotes a strict HTTP(S)/hostless local-file
  subset behind persistent Ask/Deny policy, active-pane confirmation and burst
  suppression. A parsed URL never grants open authority.
- **Phase 30 / OSC 1337 RequestAttention** implements the documented
  yes/once/no/fireworks set behind persistent Deny/Allow-with-limits policy.
  AppKit IDs are session-owned and bounded; the cursor-local effect is
  theme-derived, Reduce Motion safe and non-interactive. The protocol never
  activates the app or grants unrelated host authority.
- **Phase 31 / OSC 99 interactive reports** keeps all callbacks in the fixed
  protocol response grammar. Only explicit user activation, one-based button
  choice, dismissal or tracked expiry can report; stale/cross-session actions
  fail closed and no button label is ever executed.
- **Phase 32 / OSC 1337 inline buttons** implements the documented copy and
  custom controls. Parser ingress creates only bounded presentation state;
  explicit activation revalidates the live visible button. Copy returns exact
  retained block text and custom can write only the fixed protocol reply.
- **Phase 33 / OSC 1337 ReportVariable** implements a closed variable surface
  behind exact-name future Allow/Deny decisions. The first request and every
  denied, undefined or unsupported request receive an empty reply; values come
  only from current terminal/product-owned state, never host environment or
  files. Reply tokens are one-shot and bound to the current session epoch.
- **Phase 34 / OSC 1337 UnicodeVersion** implements the documented 8/9 width
  switch and bounded optional labels for push/pop. Width state is terminal-
  local, snapshot/resize safe and denied for VT220; it cannot trigger a host
  action or persist a profile change.
- **Phase 35 / OSC 1337 ClearCapturedOutput** implements the exact documented
  clear against Ianvs's existing per-session Captured Output collection. Open
  product UI refreshes to its empty state; terminal rows, scrollback and other
  sessions are preserved, and the command grants no host authority.
- Unsupported/deferred OSC must remain a bounded no-op without product-state
  mutation. Host actions remain policy-gated, JSON compatibility remains additive,
  and protobuf tags must not be reused.
