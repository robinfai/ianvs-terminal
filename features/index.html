Features

把本地终端的日常体验先做好。

会话、窗口、交互和视觉状态保持明确。ianvs 先把桌面终端最常见的动作做稳。

Local shell

本地 shell，不绕路

打开本地会话，运行常见开发命令，围绕真实工作流组织体验。你先看到稳定可用的 shell，再按需要深入实现细节。

Workspace

清楚的桌面工作区

tab、窗口壳、profile、defaults、空状态和焦点管理都服务于同一个目标：用户知道当前在哪里、正在操作什么。

Terminal basics

终端交互基础扎实

复制、粘贴、滚动、resize、选区和退出后的恢复路径是桌面终端的基础。ianvs 把这些基础放在第一层。

Visual identity

有个性，但不吵

Carbon Neon 让产品有记忆点，Neon Paper 保持白天阅读舒服。高对比、紧凑、状态清楚是共同规则。

Built-in highlights

让终端会话更可理解。

这些亮点不只是在底层多写了几段代码，而是为了让本地 shell 更容易扩展、更容易调试，也更接近真实桌面终端的使用习惯。

01

JSON request

Native JSON 请求通道

搜索、选区文本、滚动历史导出和诊断请求可以通过同一条 native 通道扩展。对用户来说，新能力能更快接入；对实现来说，不必每次都新增一组零散接口。

02

Shell context

Shell Hook 感知终端

终端可以收到命令、当前目录、shell 和退出状态等上下文。它不再只是被动显示输出，而能为标题、最近命令、目录感知和后续工作流提供可靠线索。

03

Render path

行级渲染缓存

frame diff 说明哪些内容变了，Flutter 侧再用行级缓存减少重复排版和绘制。大输出、滚动和局部刷新时，界面只处理真正需要更新的行。

04

Diagnostics

可归因诊断导出

诊断包会把命令负载、native 解析和 Flutter 渲染分开呈现。遇到卡顿或异常时，可以先看证据指向哪里，而不是在终端、UI 和命令之间来回猜。

05

xterm-style API

xterm 风格 Dart API

对外提供接近常见终端库的 open、write、paste、resize、scroll 和 selection 能力。上层接入时可以按熟悉的终端模型使用，不必先理解 Rust 细节。

06

Input modes

模式感知输入系统

按键、粘贴、鼠标和滚动会根据当前终端模式编码，例如 bracketed paste、alternate scroll 和鼠标上报。vim、tmux、less 这类场景更容易保持正确行为。

07

Session memory

Instant Replay 轻量回放

最近的终端画面可以用轻量文本快照保留下来，帮助回看刚发生的输出变化。它不是录屏，也不改变 shell 行为，而是给问题复现和状态回顾一个更低成本的入口。
